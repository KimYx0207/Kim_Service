# 启动计划与风险优先切片：专业方法

知识修订：0.2.0，2026-11-10。本文是本包原创方法与合成算例，不是第三方包副本。

## 输入与适用范围

- 把已选方向变成能观察结果的首次交付计划
- 计划是建议，不接管宿主调度、审批或执行状态

- `chosenIdea`：已经选定的方向与本轮要完成的结果。 缺失时：先确认方向；不同时默认多个业务都启动。

完整输入/输出仍以同包 capability.json 为准；acceptanceCriteria/handoffContext 若由合同要求，应采用当前任务绑定，不能把材料当授权。

## 领域知识

- 先把已选方向转成一个目标用户能体验的最小结果，再列完成它真正必要的材料、决定和动作。没有用户结果的注册账号、搭框架或做品牌不应自动成为首个里程碑。
- 依赖来自数据、接口、授权或共享资源，而非岗位排列。两个任务互不需要对方产物且资源允许时可建议并行；存在输入依赖则写明为何等待。实际任务状态、资源租约和人工暂停由调用方管理，专业包不另建队列。
- 用最能改变方案的风险先安排小检查，并给时间/预算上限与观察条件。若材料缺失，先调整范围或排除阻塞部分；新证据改变成本、需求或可行性时重排未开始工作，不把已完成步骤数量当成功。

## 诊断顺序

### first-result：第一个交付让用户完成什么可观察动作？

检查：已选方向与目标用户；具体材料和结果验收。缺证据时：目标未选定时先交选择缺口，不把方向评估当启动。

### blocking-input：哪些动作真依赖其他产物或权限？

检查：输入输出关系；同一资源与用户必须决定的事项。缺证据时：区分阻塞和可继续部分，别把所有任务放进统一等待。

### risk-evidence：哪项未知最可能使后续工作白做？

检查：高成本/难逆部分的前提；最短验证与可承受预算。缺证据时：先做小样核对，缺结果时不预报成功。

## 决策方法

- **vertical-slice**：计划只有技术或岗位任务，没有体验结果时，按一个可演示用户结果组织交付切片及验收。拒绝：先搭大全系统再问用户是否有用。
- **real-dependency**：一项等待人工决定，但其他项输入独立时，把阻塞理由交宿主，建议继续已授权独立项。拒绝：把专业方法写成第二调度器或自动批准人工事项。
- **evidence-replan**：真实试验推翻关键假设时，说明影响并更新剩余计划、预算与停止条件。拒绝：为完成原计划继续无价值工作或篡改成功标准。

## 交付与验收

- `firstDeliverable`：明确用户可体验的最小结果和范围。 不通过情形：只有学习/建库等内部动作。
- `schedule`：每项有输入、产物、真实依赖和有限时间。 不通过情形：把前后端等角色天然串行或默认所有工作可并行。
- `budget`：仅列实际预期支出与上限/待定项。 不通过情形：把用户可用预算自动当必须花光。
- `acceptance`：条件观察目标结果并包括关键失败场景。 不通过情形：以文件数量、完成步骤或自报通过代验收。
- `nextDecision`：根据什么结果继续、改范围或停止。 不通过情形：自动扩大投入或替用户批准发布。

## 工具与实际执行

可以读取明确项目材料和已有任务/预算事实。实际排程、Sub Agent、资源与 Hook 留在宿主；本包只交依赖与检查建议。工具不可用时交人工可执行步骤，不谎报团队已经启动。

## 正例与反例

以下是作者设计的合成片段，不是模型运行记录，也不是完整正式交付；预期判断仍需独立专业复核。

### inventory-slice（可接受候选）

已选做一个合成库存核对示范，每天1小时，不需购买工具。

输入：{"chosenIdea":"给店主演示最小库存核对表","resources":"每天1小时，共7天；现有表格软件","constraints":"只用合成数据，不访问客户系统"}

候选输出片段：

```json
{
  "firstDeliverable": "一张可输入期初、入库、出库并核对期末的合成演示表。",
  "budget": [
    "本轮新增现金支出0；不因可用200元就购买工具。"
  ],
  "acceptance": [
    "输入10、5、3，期末应为12；空值与负库存有明确提示；未进行真实客户交付。"
  ]
}
```

判断理由：最小结果可演示、可验算，支出与授权没有被扩大。

### unnecessary-block（应拒绝候选）

主视觉需用户选择，但合成计算校验不依赖该选择。

输入：{"chosenIdea":"演示库存核对工具","resources":"计算规则已定；封面风格等用户选择","constraints":"计算样例与风格独立"}

候选输出片段：

```json
{
  "schedule": [
    "先等全部视觉问题得到答案，在此之前所有合成计算和资料核对都暂停。"
  ]
}
```

判断理由：将局部决定变成无依据的全局阻塞；应把真实依赖交宿主调度。

## 失败与人工边界

- 涉及受监管业务、法律合同或金融投入时由合格人员审核对应部分。
- 用户决定业务投入与公开发布；普通内部草稿或合成小样可按现有授权推进。
- 必要事实/能力缺失时交具体影响和下一步，不伪造执行；只停止受影响部分，整体调度由调用方决定。
- 专业效果状态是 `not_evaluated`；合同验证和资料完整字节交接只证明结构与来源运输，不能代替真实任务质量。
