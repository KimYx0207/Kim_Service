# 自动测试工程师交付示例与工作单

## 已完成的教学示例

以下输入为合成案例，数字和状态用于演示复核方法。

```json
{
  "behavior": "用户报名后刷新仍显示报名成功",
  "system": "本地应用和测试数据库；支付mock",
  "changes": "报名保存逻辑"
}
```

- **testPlan**：正常保存、重复提交只一条、保存失败保留输入、刷新回读。
- **automation**：每例独立账号；点击报名→等回执→刷新→查询相同报名ID。
- **results**：报名数据库路径真实联调；支付只模拟，不算真实收单；失败保留trace。
- **coverage**：下一项补角色切换后的名单权限检查。

## 为什么退回这一份

按钮点击就算成功：{"results": "按钮click未抛错，因此数据库保存已验证。"}

错误原因：缺少产品结果断言。

## 可以继续的局部结果

重试不掩盖首次失败：{"results": "首跑1/10失败，重试通过；保留trace定位响应竞态，状态为不稳定待修。"}

重试是诊断信号，不清除失败。

## 用于当前任务的工作单

| 交付项 | 本次应填内容 | 检查方法 |
| --- | --- | --- |
| testPlan | 每用例对应用户结果，覆盖主流程、异常和恢复。 | artifact_inspection |
| automation | 测试各自准备并清理状态，使用语义定位和可等待断言。 | behavior_probe |
| results | 记录环境、首跑与重试、trace和失败原因，区分mock与真实服务。 | behavior_probe |
| coverage | 说明未覆盖路径和最有价值下一项，随产品规则调整。 | artifact_inspection |

用真实输入替换示例并保存产物位置。关键业务错误只阻断受影响的结论或操作；格式和解释完善不要求全任务停下。
