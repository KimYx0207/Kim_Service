# 可靠性工程师工作方法

## 目标与执行

围绕用户能否完成任务设计服务目标、监测、金丝雀发布和故障恢复。

1. 选关键用户旅程和依赖，区分服务整体与单一路线影响。
2. 从实际请求定义SLI/SLO，记录成功分子、有效分母、时窗和排除规则。
3. 比较候选与基线同类流量；设置样本下限、最长观察、错误/时延/成本阈值。
4. 小范围运行，阈值触发时熔断候选并回到已验证版本；独立服务继续。
5. 在隔离环境演练失败及恢复，验证冷却后探测、限次恢复和回退后用户结果。

## 关键判断

- 当监测缺失或0个样本：维持当前范围并修复观测；避免把unknown写成pass。
- 当候选触发错误阈值：停止该路线放量并回退；避免阻断所有独立工作。
- 当冷却结束：用有限探测恢复；失败重新熔断；避免立即全量重启。

## 领域细节

熔断器状态至少有closed/open/half-open，记录触发原因、作用范围和下次允许探测时刻。恢复探测限制并发与次数，避免集体重试。发布回滚不自动回滚数据库数据；先验证版本兼容及重复操作语义。阈值来自本次SLO和成本预算，文中示例数值不是全局默认。

## 输入不全时

- `service`：用户旅程、服务依赖和受影响范围。先挑一条关键旅程建立基线。
- `signals`：请求、错误、时延、资源和历史事件。缺监测先补采样，缺值不当零。
- `release`：基线/候选版本、发布范围、容量及回退方式。先验证回退对象和配置，未准备好仅暂停放量。

缺少非关键资料时，先给明确假设下的草案或局部结果；资料补齐后只重验受影响部分。授权已覆盖的可逆工作继续，不重复确认。

## 参考方法的用途

- Google SRE canarying releases：用可比较的基线和小流量观察决定推进或回退。

出处和适用边界见 [PROVENANCE.md](../PROVENANCE.md)。本包方法、案例和工作单为原创整理。

## 可运行参考计算

本包提供 `scripts/evaluate-canary.mjs`，以命名导出函数处理明确输入；运行 `node tests/calculation.test.mjs` 可复算本例和边界反例。它是局部参考算法，生产环境的权限、数据来源和完整业务路径仍按当前任务核验。

比例阈值在达到本次最少样本后判断，少量偶发失败继续观察。已观察到越权、数据损坏等关键不变量失败时，用单独的 `criticalFailure` 信号立即停止候选；不要把所有普通请求失败当作该信号。
