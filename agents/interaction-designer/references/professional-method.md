# 交互与视觉设计知识装配

方法版本：0.3.0。仅用于当前 interaction-designer 任务。来源修订与采用边界见 ../PROVENANCE.md；本页提供原创专业方法，不宣称完成用户测试、浏览器检查或视觉验收。

## 用真实任务确定设计

先核对当前 designBinding、journey、已定决定、实际内容、品牌/组件库和目标设备。记录视觉资产、组件版本及现有页面证据；未拿到截图不能声称看过界面。理解“谁在什么情境做什么，怎么知道完成，失败后如何继续”，再选择页面结构。

给用户比较的是体验选择：例如“保留草稿后逐段合并”与“先另存副本后整体替换”，要说明成本、错误风险和适用情境。两套颜色、工具品牌或字体不构成产品决策。已定选择不重复询问；尚未知的内容标明影响的模块和需要的事实。[domain-modeling]

## 从旅程到可交付规格

1. 为进入、操作、完成、继续/退出和恢复建立状态表。每行含触发、可见反馈、保留数据、允许动作、下一状态与验收项；覆盖相关空态、加载、权限失效和错误，避免堆无关状态。
2. 用真实长短内容排信息优先级；主要动作名称对应结果。给标题层次、间距、字体角色、颜色/对比、窄屏重排及溢出行为，不用“高级感”替代规格。[anthropic-frontend]
3. 复用现有视觉系统；新方向可以提出不同构图，但每项选择必须有读者任务或品牌依据。装饰不能制造错误层级；动效说明触发、反馈、持续时间、取消和 reduced-motion 行为。
4. 用语义控件优先；模态设计明确焦点进入、Tab 范围、Escape/取消、背景不可交互及关闭后焦点目标。焦点可能应在标题、首个控件或较安全操作，依内容决定，不能固定一刀切。[w3c-dialog]
5. 交付模块规格回到同一 productDesign.softwareDesign：引用既有 journeyRefs、stateRefs、decisionRefs、接口和验收 ID，不另造状态真源。设计师补交互细节，不自行批准技术栈或重排调用方任务。[spec-kit-spec]

## 正例与反例：移动端冲突处理

反例：在小屏把两份正文挤成双列，仅提供“确定”，关闭后焦点回 body；截图好看，但读不清差异、含义不明且用户可能丢稿。

正例：小屏上下比较并突出版本来源；按钮说明“保留本机副本”“查看差异”“返回编辑”。取消保留草稿和滚动位置；失败可重试且不重复提交。若采用模态，给出焦点路径；若用独立页面，则定义返回位置和历史导航。两种方案说明何时适用，不能因参考样例有模态就强行套用。

## 验收必须对应实际体验

| 维度 | 需观察的结果 |
| --- | --- |
| 可理解 | 用户知道当前版本、动作后果和恢复方法；用真实内容演示 |
| 可操作 | 键盘可完成关键路径，焦点可见且返回合理；触控目标不重叠 |
| 可恢复 | 取消/返回/失败保留必要输入；重复动作有清楚反馈 |
| 布局 | 目标窄屏、长文本、放大和错误文案无关键遮挡或不可达操作 |

reviewEvidence 逐项列环境、页面/原型版本、操作、预期、观察、截图/录屏引用及缺口。纯设计稿只到 design_only；自动检查不证明审美或用户理解。由实际观察推修订理由，并保留用户已定决定。knowledgeUsage 只列实际进入本任务上下文的资料。
