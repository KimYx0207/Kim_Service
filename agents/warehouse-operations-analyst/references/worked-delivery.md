# 仓储履约分析师：合成交付演练

所有数值、条款、设备、账户和业务对象均为合成教学材料；预期判断尚未经过真实行业任务评测。

## 输入

```json
{
  "inventory": {
    "sku": "A",
    "unit": "件",
    "onHand": 100,
    "reserved": 30,
    "blocked": 10,
    "statesDisjoint": true,
    "batches": [
      {
        "id": "B1",
        "available": 40,
        "remainingDays": 2
      },
      {
        "id": "B2",
        "available": 20,
        "remainingDays": 30
      }
    ]
  },
  "orders": {
    "quantity": 70,
    "minimumRemainingDaysAtDelivery": 7,
    "delivery": "当日"
  },
  "operations": "状态与单位已核，未执行出库"
}
```

## 分析与可复核结果

合成SKU-A在库100件，已预留30件、质量冻结10件，两类互不重叠，确认可配60件。新增订单要70件，应报告缺10件，不能用100件承诺。可配批次B1为40件、两天后到期；B2为20件、30天后到期。若客户要求到货时至少7天保质期且当日到货，只有B2满足，能配20、缺50。
两个订单分别要15件，不得都独立将B2的20件当全额可用；分配账必须显示第一单15、第二单5与剩余不足10。

## 当前交付字段

- `availability`：SKU-A100件−预留30−冻结10=60可配，题设状态互斥；客户要求至少7天剩余保质期，当日到货，仅B2的20件满足。
- `allocationPlan`：订单70件，候选分B2 20件，未满足50件；B1虽有40件但仅剩2天，不满足本订单，不允许替代。分配尚未写回业务系统。
- `processImprovements`：本次不足来自适配批次量而非总库存不足；执行前刷新B2余额并扫码核SKU、批次、数量与单位。没有现场误拣样本或行走数据，不能声称动线效率改善。
- `controlMetrics`：记录订单行需求70、符合约束候选20和不足50；实际准时足量交付须等出库/签收，当前不能将模拟候选算成功发货。盘点或异常按原事件ID跟踪。
- `facts`：本例所有对象和数值为合成，来源是本页input对应字段；未提供的真实文档、观察日或外部事实均不补造。各已给单位、日期和条款版本按原字段保留。
- `limitations`：仅完成所示条件推导与文本分析；未连接实际业务系统、未验证真实来源，未执行外部变更。缺口及其影响已经分布到各领域输出。
- `handoff`：本页作为合成交付示范；实际任务按delivery-template和method.json交同名字段、原材料位置与逐项检查证据。将上述待核材料交当前调用方继续，不创建新的授权或业务状态。

以上覆盖当前合同全部必填字段；它是合成输入的完整交付演练，不是实际业务验收。

## 看起来完整但应拒收

```json
{
  "allocationPlan": "库存100大于70，直接全部承诺；优先发出快过期B1。"
}
```

忽略预留、冻结及客户保质期约束。

## 材料不全时仍能交什么

- `availability`：库存单位与需求单位不可直接相减；先核SKU包装换算，其他同单位SKU可继续分配。
