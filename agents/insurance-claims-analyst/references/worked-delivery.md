# 保险理赔材料分析师：合成交付演练

所有数值、条款、设备、账户和业务对象均为合成教学材料；预期判断尚未经过真实行业任务评测。

## 输入

```json
{
  "policy": {
    "order": "先免赔，再80%赔付，再剩余限额",
    "deductible": 100,
    "insurerShare": 0.8,
    "remainingLimit": 650,
    "currency": "CNY",
    "deductibleRemaining": 100
  },
  "claim": {
    "eligibleExpense": 1000,
    "unverifiedExpense": 200
  },
  "evidence": "合成发票明细与条款已定位，未提供核赔或支付回单"
}
```

## 分析与可复核结果

合成保单题设明确约定：先扣当期剩余免赔100，再由保险方承担80%，最后受剩余限额650约束。题设合格费用1000，先取max(1000−100,0)=900，再乘0.8得720，最后min(720,650)=650。未核费用200单列。这里只核所给条件算式，保障期间、责任适用和真实已用额仍须原始材料确认；650不是已核赔或已支付。
顺序边界：若剩余限额为1000，先免赔再比例结果为720，先比例再免赔为700，必须按实际条款选；650截顶恰好相同不代表算法顺序可互换。若合格费用为50、剩余免赔100，按本例顺序可赔为0，不能返回−40。免赔已消耗多少应独立取得证据，本例输入明示剩余为100。

## 当前交付字段

- `coverageMap`：policy仅提供扣减顺序与金额参数；事故日期、保险期间和责任全文未给。claim中的1000是题设合格金额，200为未核费用，不能将其转为完整责任覆盖结论。
- `amountReview`：依题设剩余免赔100：max(1000−100,0)×0.8=720，受剩余限额650限制为650。低费用不得负数；高限额情景需保留720/700顺序差异。
- `evidenceGaps`：补事故日期与被保险主体、有效保单/批单、费用行ID、免赔及限额已用记录；每项分别用于核期间、责任、重复或剩余额度。200未核费用独立追证。
- `reviewPacket`：本页交条件金额650和条款核对清单；核赔决定、拒赔理由、实际付款均未提供，不宣称通过核赔或已到账。
- `facts`：本例所有对象和数值为合成，来源是本页input对应字段；未提供的真实文档、观察日或外部事实均不补造。各已给单位、日期和条款版本按原字段保留。
- `limitations`：仅完成所示条件推导与文本分析；未连接实际业务系统、未验证真实来源，未执行外部变更。缺口及其影响已经分布到各领域输出。
- `handoff`：本页作为合成交付示范；实际任务按delivery-template和method.json交同名字段、原材料位置与逐项检查证据。将上述待核材料交当前调用方继续，不创建新的授权或业务状态。

以上覆盖当前合同全部必填字段；它是合成输入的完整交付演练，不是实际业务验收。

## 看起来完整但应拒收

```json
{
  "amountReview": "全部1200先乘80%并重复扣两次100；已赔付760。"
}
```

把未核费用并入、违反明确扣减顺序且无回单宣称支付。

## 材料不全时仍能交什么

- `coverageMap`：先提取各版本责任和生效日期冲突，费用与证据核对继续；受批单歧义影响的覆盖判断保留条件。
