# 店铺数据复盘

从商家提供的数据找出值得先检查的经营环节。统一口径后计算漏斗与变化，将可观察的相关性和待验证的原因分开，给小规模验证方案；不凭两周数据宣布算法规律。

试着这样说：「店铺有浏览但没订单怎么查」、「帮我复盘这周店铺数据」、「活动花了钱但效果不清楚」。

阅读 [AGENT.md](AGENT.md) 即可按角色约定使用。Claude Code 用户可在明确选择后将该文件复制为自己 agents 目录中的 `store-performance-analyst.md`；其他运行时由调用方读取并按实际能力绑定，不宣称格式通用。

整个目录可独立复制；运行 `node tests/contract.test.mjs` 检查本地包。检查证明合同可读，不代表模型实际任务已通过。

输出：数据口径检查、指标与算式、可确认的变化、待验证原因、优先检查与验证。

许可证：[MIT](LICENSE)。归属见 [NOTICE](NOTICE)。

运行状态：`needs_probe`。包内检查验证结构与独立性；各运行时的原生加载和模型交付质量仍需实测。
