# 数据管道工程师工作方法

## 目标与执行

把多源数据变成可重跑、可回补并能追到异常记录的数据管道。

1. 读取源及消费者合同，明确业务键、事件时间、入库时间和删除语义。
2. 选固定分区和水位策略，设计暂存后原子替换或幂等合并，明确提交点。
3. 实现或给出SQL/任务补丁，同时保留源批次与输出血缘。
4. 用重复事件、迟到事件、空批次、删除和重跑验证主键集合及金额守恒。
5. 先回放一个分区，对照质量/耗时后扩大；失败只隔离该分区并保留已完成产物。

## 关键判断

- 当可重跑任务：绑定输入分区或快照；避免重跑读取随时变化的latest。
- 当数据重复投递：按业务键及版本处理并对账；避免只盲目追加。
- 当单分区失败：保留成功分区、隔离失败批次；避免全部清空重建。

## 领域细节

业务键去重需区分合法更新和重复投递：同键较新版本可替换，冲突版本进入异常清单。金额以最小币值或数据库定点数计算，不能跨币种相加。回补包含原始输入日期、水位和消费者重算范围。提交成功但调度回执丢失时先核对目标批次标记，避免重复写入。

## 输入不全时

- `sources`：源表/文件、主键、变更事件和读取权限。先做源映射草案，未读的数据不假定存在。
- `target`：输出粒度、消费者、时区、刷新和保留要求。先说明候选粒度，避免把明细和汇总混在同表。
- `operations`：运行窗口、失败恢复、回补区间和资源预算。从单分区验证开始，扩大范围前观察成本。

缺少非关键资料时，先给明确假设下的草案或局部结果；资料补齐后只重验受影响部分。授权已覆盖的可逆工作继续，不重复确认。

## 参考方法的用途

- Apache Airflow task best practices：任务按固定分区读取并使重跑得到相同结果。
- dbt data tests：把唯一、非空、值域和关联约束转成返回异常行的检查。

出处和适用边界见 [PROVENANCE.md](../PROVENANCE.md)。本包方法、案例和工作单为原创整理。

## 可运行参考计算

本包提供 `scripts/replay-partition.mjs`，以命名导出函数处理明确输入；运行 `node tests/calculation.test.mjs` 可复算本例和边界反例。它是局部参考算法，生产环境的权限、数据来源和完整业务路径仍按当前任务核验。
