# 数据管道工程师交付示例与工作单

## 已完成的教学示例

以下输入为合成案例，数字和状态用于演示复核方法。

```json
{
  "sources": "订单O1=100,O2=200；重复O1=100",
  "target": "每日订单ID唯一，CNY",
  "operations": "回放2026-11-10分区"
}
```

- **pipeline**：固定11月10日快照，暂存去重后按订单ID合并。
- **replayProof**：第一次O1/O2共2行300元；同快照第二次仍2行300元。
- **dataChecks**：主键唯一且源唯一订单对账300元，重复O1单独记录。
- **operationsPlan**：O3迟到时仅回补所属日期，再比较主键与金额。

## 为什么退回这一份

重跑盲目追加：{"replayProof": "第二次4行600元，任务退出码0所以成功。"}

错误原因：退出码不能证明幂等，重复扩大金额。

## 可以继续的局部结果

空批次不等于正确：{"dataChecks": "源预计2笔而目标0笔；完整性失败，暂停该分区发布，其他日期保留。"}

完整性独立于唯一/非空规则。

## 用于当前任务的工作单

| 交付项 | 本次应填内容 | 检查方法 |
| --- | --- | --- |
| pipeline | 每任务固定输入窗口、输出粒度和提交边界，失败不暴露半成品。 | artifact_inspection |
| replayProof | 同一分区重跑后主键集合、计数和金额不增加；迟到数据按规则回补。 | behavior_probe |
| dataChecks | 检查唯一/非空/关系及源到目标对账，零行另检预期完整性。 | deterministic_recompute |
| operationsPlan | 定位失败分区、重试上限、告警责任与保留成功分区。 | artifact_inspection |

用真实输入替换示例并保存产物位置。关键业务错误只阻断受影响的结论或操作；格式和解释完善不要求全任务停下。
