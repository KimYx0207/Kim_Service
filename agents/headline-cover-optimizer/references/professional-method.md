# 标题封面与承诺一致性：专业方法

知识修订：0.3.0，2026-11-18。本文是本包原创方法与合成算例，不是第三方包副本。

## 输入与适用范围

- 基于已完成的正文、脚本或核心事实要点，设计多组差异化标题与封面视觉方案
- 逐项审查“外层点击承诺”与“内层正文兑现”的一致性，提高有效目标受众点击而非制造高跳出标题党
- `bodyOrKeyPoints`：正文真实包含的论据、步骤、数据与结果边界。缺失时：先索取正文或核心事实提纲，绝不对着一句空泛主题词硬造夸张数字标题。

完整输入/输出以同包 `capability.json` 为准；`acceptanceCriteria` / `handoffContext` 若由合同要求，采用当前任务绑定。

## 1. 标题 × 封面“信息互补法则”（Zero Redundancy Rule）

新手最常见的专业度硬伤，是把 18 个字的标题原封不动再印在封面上，浪费一半展示带宽。标题与封面应当分工互补：

| 组合模式 | 封面承担的 0.5 秒第一眼职责 | 标题承担的 1.5 秒补充职责 | 适用内容类型 |
|---|---|---|---|
| **结果实物 + 限制条件** | 展示最终成品特写或前后同框对比 + 3~6 字极短核心标签 | 说清适用人群、前置成本或具体达成路径 | 改造、设计、编程作品、美食、效率工具 |
| **反常痛点 + 机制拆解** | 具象化呈现读者最熟悉的报错/翻车现场 + 核心疑问词 | 点明背后的真实原因与解决切口 | 避坑复盘、排障教程、行业观察 |
| **结构清单 + 筛选标准** | 清晰呈现分类框架图、对照表局部或关键物件集合 | 说明筛选维度、实测范围与使用场景 | 横评对比、书单/工具单、流程梳理 |

## 2. 主流平台移动端缩略图与安全区核查表

双列流与信息流中 85% 以上曝光发生在手机小屏，设计封面方案时必须避开平台 UI 遮挡死角：

| 平台场景 | 常用画幅比例 | 移动端高频裁切与 UI 遮挡死角 | 字体与层级硬指标 |
|---|---|---|---|
| **小红书双列流** | `3:4` 竖版为主（兼容 `1:1`） | 右上角图集/视频角标；底部边缘紧贴标题栏易显拥挤 | 主视觉字不超过 2 行，单行 `<= 7` 字；缩至 `160px` 宽仍清晰可辨 |
| **B 站 / YouTube 推荐流** | `16:9` 横版 | 右下角时长黑底角标（严禁放关键数字或印章）；个人主页列表偶有居中裁切 | 主体占画面 `40% ~ 60%`，背景降噪拉开明度反差，最多 `1` 个视觉焦点 |
| **抖音 / 视频号信息流与主页** | `9:16` 全屏播放 + `3:4` 个人主页网格 | 播放页右侧点赞头像栏、底部文案与进度条；**主页网格会上下裁切成 `3:4`！** | 核心封面大字必须锁定在画面中央 `3:4` 与 `16:9` 交集安全区内 |
| **微信公众号消息列表** | 首条 `2.35:1`，次条/转发 `1:1` | 分享卡片与合集列表会自动居中裁切为 `1:1` 正方形 | 核心主体与主标题文字必须严格置于正中央 `1:1` 安全框内 |

> **执行诚实边界**：仅输出构图、文案层级、配色对比与安全区规格时，必须标注“封面设计方案（未渲染成图）”；仅当实际读取图片或完成缩略图视觉检查后才记录视觉核验结果。

## 3. 诊断顺序与决策规则

1. **promise（正文兑现核查）**：逐句定位正文中真实存在的数字、人物关系、时间跨度与前提条件。
   - **truth-before-strength**：若强吸引力标题暗示了正文并未证实的收益（如把练习 Demo 写成线上投产节省百万），立即砍掉夸大修饰，改为准确的具体问题承诺。
2. **complement（文图分工与可读性）**：用标题立具体场景，用封面给视觉证据，删除重复赘字与空洞感叹词。
3. **no-causal-shortcut（CTR 混杂变量归因）**：
   - 当推荐流放量进入更宽泛的陌生人群池时，总曝光大涨往往伴随整体 CTR 自然回落，这属于人群稀释效应而非标题变差；只有同流量入口（如仅看搜索流或仅看推荐首池）、同时段对照组才具备可比性，绝不妄下“触发平台惩罚”之类无证据断言。

## 交付与验收核对点

- `promise`：一句话锁定标题与封面共同传达且正文 100% 兑现的核心收益。
- `titleCandidates`：按不同切角（痛点提问角、具体结果角、反常识误区角、方法清单角）提供差异化备选，而非同一句话换同义词。
- `recommended`：说明首选组合适配当前受众与素材的理由，并指出上线后优先观察的验证指标。
- `coverOptions`：明确画面主体、主副文案字数、画幅比例、UI 避让安全区及当前制作状态。
- `consistencyCheck`：逐项核验数字口径、案例性质（真实 vs 合成演示）、人物身份与适用条件无夸大偏移。
