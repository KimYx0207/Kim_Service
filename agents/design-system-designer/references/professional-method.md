# 设计系统设计师工作方法

## 目标与执行

把分散页面整理成一致的语义token、组件状态和可迁移的设计系统。

1. 盘点现有组件和页面，用截图及代码位置合并真正同义的模式。
2. 先定义颜色、排版、间距的语义角色，再绑定原始值；按项目格式验证引用。
3. 为每组件补状态矩阵、键盘行为、错误恢复和可访问名称。
4. 用真实表单和列表试用，检查长中文、英文、日文、数字及主题变化。
5. 先迁移一个页面观察问题，再推广已验证组件；保留旧新映射和版本记录。

## 关键判断

- 当多主题共用组件：组件引用语义token；避免组件直接引用某主题色号。
- 当token引用相互依赖：定位循环并重新建层次；避免默认成空值继续发布。
- 当组件视觉评审：使用真实内容和异常状态；避免空白占位页代表所有场景。

## 领域细节

语义token描述作用，不绑定某个屏幕。组件API要说明受控/非受控、值变化、错误信息关联、加载时可否取消。迁移采用旧名别名或兼容适配，删除旧组件前查消费者；去重不应合并语义不同但当前颜色相同的token。视觉和行为由不同检查记录，格式可导入不表示交互已经合格。

## 输入不全时

- `surfaces`：已有页面、组件、真实内容和用户任务。先盘点现有样例，缺页不虚构已审查。
- `identity`：品牌色、字体、语言、密度和平台。可先给可替换语义角色，未定品牌参数保留选项。
- `constraints`：框架、兼容范围、可访问性目标和迁移节奏。先完成一个组件族试用。

缺少非关键资料时，先给明确假设下的草案或局部结果；资料补齐后只重验受影响部分。授权已覆盖的可逆工作继续，不重复确认。

## 参考方法的用途

- Design Tokens Format Module 2025.10：声明token类型与引用，检测循环并把语义映射到组件。
- Storybook accessibility testing：为组件各状态配套可检查故事和自动化可访问性检查。
- W3C WCAG 2.2 quick reference：按适用成功标准检查键盘、焦点、名称、对比度和错误恢复。
