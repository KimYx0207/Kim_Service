# 可编辑的预约台样板

直接打开 [预约台页面](../examples/service-console/index.html)。这是原创合成数据，不连接业务系统，也不是客户成果或专业效果认证。

## 修改入口

`examples/service-console/config.js` 是业务示例和设计默认值的唯一配置：品牌、时段、项目、初始预约、主题/密度选项、字号与品牌色、模拟延迟均在此。`tokens.js` 只负责引用解析和颜色对比度计算；`app.js` 负责展示与本地交互；`styles.css` 负责布局。不要把可变业务数据再写回 HTML。

页面可以切换浅深主题、密度、字号、品牌色，并下载当前 tokens JSON。两个区域共用语义颜色、间距与状态定义；颜色引用循环会被解析工具拒绝。下载的是当前可编辑配置中的 tokens，不是截图。

## 实际交互

先用空表单检查必填，再填写示例姓名与 `demo@example.test`。勾选失败模拟后提交，查看加载防重和失败提示；输入应完整保留，再次提交可添加本地预约。名单支持到店/待到店切换。重置不会留下之前加载回调追加的旧记录。

再用键盘操作，检查可见焦点、必填提示、长英文按钮、390px窄屏、浅深主题与大字。HTML/源码可直接复制到当前任务，但应替换本次事实和接口；没有真实后端时不得宣称已发邮件或完成真实预约。

## 交付到项目

保留当前项目设计系统和接口。先把一个真实任务接到样板结构，迁移语义tokens与组件状态，再扩展其他页面；样板不要求重建整个品牌。随交付提供实际源文件、截图/操作证据和未验证项。工作单中的文字不代替可打开页面，页面存在也不代替视觉与行为验收。
