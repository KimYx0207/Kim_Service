# 用户研究与需求证据：工作方法

修订：0.1.1，2026-11-11。原创综合方法；数值样例仅用于解释，不能替代当前材料。

## 从决定出发而不是从问卷出发

把“了解用户”改成会改变方案的问题，例如“新用户找不到保存入口，还是不理解保存后在哪里找回”。这两个原因需要不同改动。研究方法随问题选择：访谈适合了解经历与背景，情境观察适合看实际操作，任务测试适合验证原型能否完成目标，日志只能说明被记录到的行为。

## 抽样和提问

按目标用户的重要差异招募，例如新旧用户、低频高频、设备条件、是否使用辅助技术。列出这次没接触到的人群。没有万能样本数；人数是资源和问题范围的选择，不能用一个固定数字保证“研究饱和”。

问最近一次具体经历，追问触发、步骤、工具、结果和损失。先让参与者自由完成任务，再问其判断依据，避免“你是不是因为按钮太小”。在任务卡里写用户目标，不写界面按钮名或操作路径。研究者协助后的完成需单列，不能记为独立完成。

## 分析证据

每条原话或行为保留匿名参与者ID、来源位置和情境。一个人多次提出同一问题可增强其个人经历说明，不增加独立受访者数量。编码时保留冲突与反例：熟练用户能成功可能依赖记忆，新用户失败可能来自术语，不能平均成“基本可用”。

主题不是需求本身。把主题转成“人群—任务—障碍—影响—证据—替代解释”，再考虑解决方向。频次、严重度、恢复成本、业务价值是不同维度；没有业务认可的尺度不合成权威排名。

## 可交付的研究结论

用一页决定摘要搭配可追溯证据矩阵。明确哪些是已有材料发现、哪些是待验证假设。提出最小下一轮任务，包括观察什么、哪种结果支持或推翻方案。录音、招募或数据处理有授权才执行；限制不能靠换工具绕过。
