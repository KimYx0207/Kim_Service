# 设备维护与可靠性工程师：合成交付演练

所有数值、条款、设备、账户和业务对象均为合成教学材料；预期判断尚未经过真实行业任务评测。

## 输入

```json
{
  "assets": {
    "assetId": "A",
    "function": "合成输送设备",
    "requiredServiceHours": 504
  },
  "events": {
    "operatingHours": 480,
    "failures": 4,
    "activeRepairHours": 8,
    "waitingPartsHours": 12,
    "verificationHours": 4
  },
  "policy": "MTTR使用主动维修；可用率使用整个服务窗口"
}
```

## 分析与可复核结果

合成设备A，观察期实际运行480小时，4次故障；主动维修总计8小时，另等待备件12小时，验证4小时。描述性MTBF=120运行小时，主动维修MTTR=2小时/次；恢复全过程平均为24÷4=6小时/次。若所需服务窗口504小时，实际窗口可用率480÷504≈95.24%。不能用主动维修2小时掩盖等待与验证。
后续若取得同部件多次异常记录，仍需核润滑、安装、负载与污染证据，才能区分失效机理；本例尚无逐事件根因证据。

## 当前交付字段

- `failureMap`：设备A有4次故障的汇总输入，未提供逐事件报警、负载或部件检查，不能给已确认根因；同一故障去重还需事件ID。
- `reliabilityMetrics`：运行480小时/4=MTBF120小时；主动维修8/4=MTTR2小时；等待12+验证4+维修8共24小时，恢复平均6小时；服务窗口504下可用率480/504≈95.24%。
- `maintenancePlan`：先补4次事件时刻及失效模式，比较待料占12小时与维修8小时的影响；可评估备件可用性与模式针对性检查，未给备件成本和风险，不决定更换周期。
- `returnToService`：需现场记录功能、质量与保护检查及负载条件；本例只有历史汇总，没有本次复产验收证据，交责任人按既有方案执行并观察同模式复发。
- `facts`：本例所有对象和数值为合成，来源是本页input对应字段；未提供的真实文档、观察日或外部事实均不补造。各已给单位、日期和条款版本按原字段保留。
- `limitations`：仅完成所示条件推导与文本分析；未连接实际业务系统、未验证真实来源，未执行外部变更。缺口及其影响已经分布到各领域输出。
- `handoff`：本页作为合成交付示范；实际任务按delivery-template和method.json交同名字段、原材料位置与逐项检查证据。将上述待核材料交当前调用方继续，不创建新的授权或业务状态。

以上覆盖当前合同全部必填字段；它是合成输入的完整交付演练，不是实际业务验收。

## 看起来完整但应拒收

```json
{
  "reliabilityMetrics": "MTTR只有2小时，因此4次总停机8小时，设备可用率98.36%。"
}
```

遗漏待料与恢复验证，把主动维修指标错当总不可用时间。

## 材料不全时仍能交什么

- `reliabilityMetrics`：200运行小时未观察到故障；不能估算有限样本MTBF，也不能据此取消维护。
