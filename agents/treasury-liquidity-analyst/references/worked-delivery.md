# 企业资金与流动性分析师：合成交付演练

所有数值、条款、设备、账户和业务对象均为合成教学材料；预期判断尚未经过真实行业任务评测。

## 输入

```json
{
  "balances": {
    "bookCash": 120,
    "restrictedCash": 20,
    "currency": "CNY",
    "unit": "万元"
  },
  "cashFlows": [
    {
      "period": "第1周",
      "inflow": 30,
      "outflow": 60
    },
    {
      "period": "第2周",
      "inflow": 20,
      "outflow": 100
    },
    {
      "period": "第3周",
      "inflow": 80,
      "outflow": 20
    }
  ],
  "scenarios": {
    "minimumCash": 10,
    "uncommittedFacility": 50,
    "withinWeekSettlementOrder": "未给"
  }
}
```

## 分析与可复核结果

合成案例，单位万元：账面现金120，其中20受限，可用期初100。第一周净流入30−60，周末70；第二周20−100，周末−10；第三周80−20，周末50。最低现金要求10，所以第2周的周末净不足额为20。
周内结算顺序未知，不能把20称为峰值融资需求。若第2周100先付、20后收，最低点是70−100=−30，相对最低现金10需40；若20先收后付，最低点为−10，需20。在题设仅这些现金流且不存在其他周内变动的前提下，这两种顺序给出20至40的资金需求区间。具体需求须获取结算日/时刻。
第三周期末为正不能消除第二周断点。未承诺50额度只作条件方案；将未来回款提前属于待协商方案，不能直接改写基础预测。

## 当前交付字段

- `cashLadder`：可用期初=120−20=100万元；三周周末余额70、−10、50。cashFlows按原顺序列流入/流出，受限20未计入。
- `gapAnalysis`：第2周周末最低−10，较最低现金10不足20；两笔流量结算顺序未知，先付款则周内最低−30，需要40，先收款则需要20。20至40为题设范围，非精确筹资指令。
- `fundingOptions`：未承诺额度50从基础排除；候选是确认其提款条件与到账日在缺口之前，或协商回款/付款日期。成本、承诺和可达性都未提供，现阶段不能排序为确定最优方案。
- `monitoringPlan`：逐周保留预测快照并逐笔匹配实际收付款，重大到期细化到日；新增付款、回款时点变化或额度确认均触发重算，分别解释金额差和日期差。
- `facts`：本例所有对象和数值为合成，来源是本页input对应字段；未提供的真实文档、观察日或外部事实均不补造。各已给单位、日期和条款版本按原字段保留。
- `limitations`：仅完成所示条件推导与文本分析；未连接实际业务系统、未验证真实来源，未执行外部变更。缺口及其影响已经分布到各领域输出。
- `handoff`：本页作为合成交付示范；实际任务按delivery-template和method.json交同名字段、原材料位置与逐项检查证据。将上述待核材料交当前调用方继续，不创建新的授权或业务状态。

以上覆盖当前合同全部必填字段；它是合成输入的完整交付演练，不是实际业务验收。

## 看起来完整但应拒收

```json
{
  "gapAnalysis": "第3周期末还有50，所以无需行动；账面120全部可用。"
}
```

忽略20受限资金与第2周付款时点，末期盈余不能回填更早缺口。

## 材料不全时仍能交什么

- `cashLadder`：先按已核账户和已知付款列明细；受限金额与未定回款另列，不能给已无缺口结论。
