# 工程项目进度与成本控制师：合成交付演练

所有数值、条款、设备、账户和业务对象均为合成教学材料；预期判断尚未经过真实行业任务评测。

## 输入

```json
{
  "baseline": {
    "PV": 100,
    "unit": "万元",
    "asOf": "合成第6周",
    "version": "approved-v1"
  },
  "actuals": {
    "EV": 80,
    "AC": 90,
    "earnedBasis": "已验收工程量"
  },
  "changes": {
    "pendingAddedScopeBudget": 30
  }
}
```

## 分析与可复核结果

合成项目截至第6周，PV=100万元，按已验收工作量计EV=80万元，AC=90万元。CV=−10万元，SV=−20万元，CPI≈0.889，SPI=0.80。可说明同范围成本效率偏低、预算进度落后，不能说实际延期20%或再花10万就能追回。
若一项未批准追加工程价值30万元，分别展示原基线与追加情景，不直接把EV加30。实际竣工影响还须查看剩余关键路径、设备到货和资源。

## 当前交付字段

- `scheduleReview`：第6周观察日和approved-v1已给，工作包依赖、日历和剩余工期未给；不能推导精确关键路径或竣工日期。
- `costPerformance`：单位万元，PV100、验收EV80、AC90：CV−10，SV−20，CPI80/90≈0.889，SPI80/100=0.80；不得转成一定延期20%。
- `changeRegister`：追加预算30处于pending，未进原基线，也没有已验收完成证据，不能增加EV；需补范围、批准和工程量。
- `recoveryOptions`：可先定位成本与完成量差异，待补网络、资源和关键约束后比较重排/赶工；不得用加人或批量并行保证追回时间。
- `facts`：本例所有对象和数值为合成，来源是本页input对应字段；未提供的真实文档、观察日或外部事实均不补造。各已给单位、日期和条款版本按原字段保留。
- `limitations`：仅完成所示条件推导与文本分析；未连接实际业务系统、未验证真实来源，未执行外部变更。缺口及其影响已经分布到各领域输出。
- `handoff`：本页作为合成交付示范；实际任务按delivery-template和method.json交同名字段、原材料位置与逐项检查证据。将上述待核材料交当前调用方继续，不创建新的授权或业务状态。

以上覆盖当前合同全部必填字段；它是合成输入的完整交付演练，不是实际业务验收。

## 看起来完整但应拒收

```json
{
  "costPerformance": "已经花90，所以EV=90；SPI=0.8说明一定延期20%。"
}
```

把实际成本当完成价值，并把价值进度比错当工期比例。

## 材料不全时仍能交什么

- `costPerformance`：先计算同口径成本绩效；精确关键路径与竣工日期因逻辑依赖缺失暂不判断。
