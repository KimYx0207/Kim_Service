# 定价与成本测算：专业方法

知识修订：0.2.0，2026-11-10。本文是本包原创方法与合成算例，不是第三方包副本。

## 输入与适用范围

- 按已给成本和场景做可复算报价分析
- 不把成本底线当市场愿付价格，不提供税务/投资结论

- `offer`：售卖单位、服务范围、每单时间与目标报价。 缺失时：先明确交付单位，不能算无范围的利润。

完整输入/输出仍以同包 capability.json 为准；acceptanceCriteria/handoffContext 若由合同要求，应采用当前任务绑定，不能把材料当授权。

## 领域知识

- 先确定售卖单位和计费范围：一次、每小时、每月或一个套餐。每单位变动成本、期间固定成本、现金支出与经营者时间机会成本分别列示；不在变动与固定中重复计同一项。百分比手续费随价格变化，应写进公式。
- 若每单贡献m=P-v且m>0、固定成本F属于同一期间，则覆盖固定成本至少需要向上取整F/m单。若m≤0，增加销量不能靠这个公式得到有限盈亏平衡；如果产能不足以交付所需订单，要把不可行性明示。
- 成本计算能说明底线和风险，不能证明顾客愿付。比较报价时同时改变价格、范围、修改次数或交付期限，应说明具体差异；退款、获客、空档和税费未知时给情景而不是假精确利润。

## 诊断顺序

### unit-boundary：这一单究竟包括哪些交付和修改？

检查：售卖单位、服务范围和时间；价格含税/手续费/附加条件。缺证据时：先明确报价范围，避免用未知工作量做固定报价。

### cost-class：哪些成本随单变化，哪些属于同期间固定项？

检查：现金、时间、费率和固定支出；退款、返工与获客成本。缺证据时：列未知/情景，不默认所有未知为零。

### capacity-demand：覆盖成本所需销量能否交付，是否有需求证据？

检查：可用工时与每单时长；真实询价/成交而非成本公式。缺证据时：分开可供给和愿付证据，不给利润保证。

## 决策方法

- **separate-time-cash**：经营者时间有明确估值时，同时列现金贡献和计入时间后的贡献。拒绝：把现金剩余等同收入/利润或隐藏劳动时间。
- **nonpositive-margin**：单笔贡献不为正时，说明当前价格/范围下无有限销量可覆盖固定成本，调整价格或成本假设。拒绝：对负分母向上取整得到负的盈亏平衡单量。
- **price-experiment**：成本可估但市场愿付未知时，给有限报价情景、范围条件与验证需要。拒绝：只凭成本加成认定最佳价格和销量。

## 交付与验收

- `assumptions`：期间、单位、费用范围和缺项显式。 不通过情形：把税费/退款/获客未知写成0。
- `unitEconomics`：公式、币种与现金/时间成本分开，可复算。 不通过情形：重复计费或漏掉随价格变化的费率。
- `scenarios`：条件变化与可交付容量同时说明。 不通过情形：用没有需求依据的销量写确定收益。
- `breakEven`：贡献正才算同期间固定成本覆盖，检查产能。 不通过情形：负贡献还声称多卖就盈利。
- `recommendation`：推荐有范围、条件与未验证的愿付假设。 不通过情形：把成本推算等同最佳市场价或税务结论。

## 正例与反例

以下是作者设计的合成片段，不是模型运行记录，也不是完整正式交付；预期判断仍需独立专业复核。

### price-time-check（可接受候选）

每单2小时，时间估值30元/小时，现金手续费3元，期间固定60元。

输入：{"offer":"服务每单2小时，比较79、99、129元","variableCosts":"每单现金手续费3元；时间成本2×30=60元","fixedCosts":"本期固定60元，不含税费等未知项"}

候选输出片段：

```json
{
  "unitEconomics": [
    "计入时间后每单贡献分别16、36、66元；现金剩余不等于最终利润。"
  ],
  "breakEven": "同期间且其他假设成立时，覆盖60元固定成本分别至少4、2、1单；还要检查可用工时。"
}
```

判断理由：公式、时间与期间一致；未声称市场接受这些价格。

### negative-margin（应拒绝候选）

每单价格50，随单现金和时间成本合计70，固定100。

输入：{"offer":"每单50元","variableCosts":"每单70元","fixedCosts":"本期100元"}

候选输出片段：

```json
{
  "breakEven": "100÷(50-70)=-5，所以卖到5单就能盈利。"
}
```

判断理由：负贡献下销量增加扩大该口径亏损，没有有限正盈亏平衡量。

## 失败与人工边界

- 税务、会计、金融及法律问题由合格人员确认；普通成本算术不因此重复审批。
- 用户确认自身时间估值、可接受范围和投入，不推断个人财务风险偏好。
- 必要事实/能力缺失时交具体影响和下一步，不伪造执行；只停止受影响部分，整体调度由调用方决定。
- 专业效果状态是 `not_evaluated`；合同验证和资料完整字节交接只证明结构与来源运输，不能代替真实任务质量。
