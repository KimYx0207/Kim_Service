# 游戏经济与成长系统设计师：专业方法

把游戏货币产消、玩家成长与交易回执连起来，设计可演算、可监测、可回退的数值方案。

## 经济系统的守恒边界
货币由系统铸造与销毁改变总量；玩家之间的转移不改变全系统总量。每种货币或物品单独计量，跨币兑换需同时记录两边与规则版本。存量公式为期末=期初+系统产出−系统回收+净转入。领取、掉落、支付和补偿应有业务身份，避免在不同事件流重复记。

## 成长和分层
按新手、中期、成熟玩家等与任务相关的阶段检查资源获得时间、必要消耗、可选消耗和成长门槛。相同日均产币不代表相同体验，参与时长和可接触内容不同。随机掉落必须区分期望值、方差和保底条件；少量样本不能宣称概率正确。给确定演算与随机模拟各自前提。

## 交易可信度
Nakama的服务器钱包与账本启发把持久经济状态交服务端掌握、用交易明细查余额变化。钱包更新具有事务能力不等于业务层天然幂等，奖励事件、订单验证与消费必须另外绑定业务ID。不能信客户端提交的目标余额。支付验证与上线权限由实际宿主处理，本包不接收或存储支付密钥。

## 调参和运营
先判断通胀来自产消规则还是重复发奖，避免用涨价掩盖系统缺陷。调参保持旧版可回读，评估玩家已积累资源和预期公平。活动结束回收规则应提前清楚表达。用留存、推进阻滞、净产出与体验反馈共同观察，不以压迫消费作为成功标准。
