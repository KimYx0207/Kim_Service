# 游戏经济与成长系统设计师：专业方法

将游戏内货币产消（Faucets & Sinks）、分层玩家成长节奏、随机掉落保底数学与服务端账本控制纳入同一套可演算模型，交付可验算、可监控、可平滑回调的数值方案。

## 1. 货币与资源系统的守恒方程

任何虚拟资源都必须区分**全服总量变化**与**玩家间再分配**，严禁把交易行换手率误判为系统回收：
- **单币种全服存量公式**：
  $$\text{期末全服存量} = \text{期初存量} + \sum \text{系统铸造（Faucets）} - \sum \text{系统销毁（Sinks）}$$
- **玩家间交易（P2P / 拍卖行）**：A 付给 B 的本金不减少全服存量，**只有系统收取的交易税（Tax）才计入系统销毁**；同时这种转移会把付费/核心层的购买力传导给搬砖/产出层，必须单独测算工作室批量小号注入风险。
- **多币种双边账本**：软货币（金币）、硬货币（充值钻石）、绑定代币与养成材料必须独立建账；跨币种兑换必须在同一事务内同时记录源币种销毁量、目标币种铸造量及所依据的汇率配置版本号。

## 2. 玩家分层成长节奏矩阵（Pacing & Cohort Analysis）

全服平均日产币量毫无体验指导意义——必须按参与强度与付费分层分别验算“获取耗时（Time-to-Earn）”与“净结余率”：

| 玩家分层（Cohort） | 典型行为画像 | 必查核心指标 | 失衡信号与修正方向 |
|---|---|---|---|
| **新手期（D1 ~ D7）** | 主线推进快、系统逐步解锁 | 核心目标解锁分钟数、首次卡点位置、引导期净结余 | 刚上手即因基础养成金币枯竭卡死 → 提高一次性首通奖励而非盲目抬高永久日常产出 |
| **中坚活跃层（F2P / 月卡）** | 稳定清日常与周常副本 | 日均有效时长、刚性消耗占比（$\text{必要消耗} \div \text{日常稳定产出}$）、养成周期天数 | 刚性消耗占比 `> 85%` 导致零容错挫败；`< 40%` 则中期开始囤积溢出 |
| **高投入 / 终局层（Endgame / 高付费）** | 主养成已满、追求极品词条或赛季排名 | 可选深度水槽（洗练/外观/公会/赛季重置）吸收率、囤积半衰期 | 缺乏非战力膨胀型体面水槽，导致硬通货贬值或战力数值崩坏 |
| **回流 / 低频层** | 周在线 1~2 次、落后大部队 | 追赶机制（Catch-up）折算效率、历史积攒资源保值度 | 旧材料直接作废引发弃坑；应通过限额兑换或经验加速缩窄差距而非清零旧资产 |

## 3. 随机掉落、期望方差与保底数学

策划表中不能只写“基础掉率 1.5%”就结束——玩家感知由**分位数体验（P50 / P90 / P99 非酋黑洞）**决定：
- **无保底独立伯努利试验**：单次概率 $p$ 时，连续 $n$ 次未出的概率为 $(1-p)^n$（例如 $p=1\%$ 时，连抽 200 次仍不出货的玩家占比高达 $0.99^{200} \approx 13.4\%$！）。
- **软保底（Soft Pity）+ 硬保底（Hard Pity）综合有效概率**：调整单次概率或递增斜率后，必须重算含保底在内的**真实综合单抽期望消耗**，严禁把基础面板概率与综合含保底出货率混为一谈。
- **样本验证边界**：几十次测试服手抽不能证明掉率实现正确；验收需结合随机数种子确定性回放或足够大样本（如 $10^5 \sim 10^6$ 次蒙特卡洛模拟）核对均值、标准差与保底截断上限。

## 4. 服务端权威账本与防刷交易控制

吸收 Nakama 服务端钱包与账本分离思想（不复制源码、不接收支付密钥）：
- **零客户端信任**：客户端只能提交“意图动作”（如 `claim_quest_reward`、`craft_item`），严禁接收客户端上报的增减金额或目标余额。
- **业务幂等键（Idempotency）**：数据库事务锁不等于业务幂等——发奖、支付回调、邮件领取、合成扣料必须绑定唯一业务身份 `(player_id, action_type, event_id)`，防止弱网重发或并发双击造成双倍发奖或负库存。
- **通胀归因先于调价**：线上物价飞涨时，先查账本流水分布区分“正常活跃产消比失衡”与“复制漏洞 / 异常脚本刷金”；若是漏洞刷金却粗暴上调全服养成价格，只会惩罚正常玩家。
