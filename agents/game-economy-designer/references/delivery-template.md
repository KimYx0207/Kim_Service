# 游戏经济与成长系统设计师：交付模板

每项保留真实输入定位、判断依据与待核项。正文、表格或可编辑文件均可，不要求把自然语言硬变成执行回执。

| 合同字段 | 应交内容 | 验收时必须看到 |
| --- | --- | --- |
| `economyMap` | 货币与物品流向 | 资源定义；产消及转移规则 |
| `balanceSimulation` | 分层成长与余额模拟 | 输入配置；逐期余额；分层假设 |
| `transactionControls` | 奖励与消费一致性 | 交易记录；重复与失败场景实测或未执行说明 |
| `tuningPlan` | 调参与观察方案 | 参数版本差异；体验与经济指标；恢复方案 |
| `facts` | 输入口径与证据 | 输入清单；假设与实际事实区分 |
| `limitations` | 未核范围与适用边界 | 已完成与未完成项；适用条件 |
| `handoff` | 交付与下一步 | 实际产物；后续责任与所需输入 |

## 当前任务记录

- 输入版本、观察日、单位、主体或服务范围。
- 已核事实、假设和未取得证据分列。
- 当前产物位置、关键结果与可能推翻结论的条件。
- 逐项对照method.json的检查结果；不要把本模板填完当作验收通过。
- 下一次刷新需要哪些记录，谁能核实。
