# 供应商比较与采购条件分析：专业方法

知识修订：0.2.0，2026-11-10。本文是本包原创方法与合成算例，不是第三方包副本。

## 输入与适用范围

- 已给候选的条件比较与试单建议
- 不认证供应商，不自动询价、下单或付款

- `specification`：相同规格、单位和验收要求。 缺失时：先确定可比对象，不能把不同规格混为一组。
- `quantity`：本次需求数量，分开包装量/MOQ与实际购买量。 缺失时：不代用户决定投入。
- `currency`：报价币种及用户接受的汇率时点。 缺失时：不同币种不可用猜测汇率排名。
- `quotes`：候选原始报价、费用、交期与质量证据。 缺失时：交需要供应商补齐的字段，不伪造报价。

完整输入/输出仍以同包 capability.json 为准；acceptanceCriteria/handoffContext 若由合同要求，应采用当前任务绑定，不能把材料当授权。

## 领域知识

- 先将需求单位、包装单位和MOQ统一。实际采购量必须满足包装整倍数与最低起订量；比较需求数量对应的总付款和超购量，不把较低单价直接当本次成本更低。运费、税费、安装等未知项标待确认，不擅自记零。
- 到货成本与使用全周期成本是不同范围。对一次性小采购可先核当前到货费用；若耐用性、维护、废料或库存风险影响决定，再列证据与情景，不为了“全面”给未知故障率编精确折现数。
- 先应用用户硬约束，再比较成本、交期与质量证据。没有共同量表和用户权重不合成总分；照片、卖家自述、样品检查与独立检测是不同证据。缺质量字段不能默认为最好，也不能在缺项后重分权重。

## 诊断顺序

### same-unit：各报价是否满足同一规格和数量？

检查：规格/单位/包数/MOQ；本次需求数量与超购处理。缺证据时：不同规格先分组，条件未清楚不直接排名。

### landed-cost：哪些必要费用和交付条件已知？

检查：单价、运费及明确计税范围；用户预算、交期和付款条件。缺证据时：给已知下限/条件总额，不把未知费填零。

### quality-evidence：质量和履约证据能支持什么结论？

检查：验收标准、样品或检测记录；信息来源、日期与样本范围。缺证据时：保留待证实项；不把评分文字当合格证据。

## 决策方法

- **hard-constraints**：候选明确违反用户交期/规格/预算时，先列排除原因，再比较其余候选。拒绝：让低价格抵消不可接受的硬约束。
- **multi-dimension**：没有经用户明确的权重或统一量表时，给条件短名单与成本/交期/证据取舍。拒绝：编默认权重生成看似客观的第一名。
- **trial-evidence**：关键质量差异仅为自述时，建议最小获授权样品验证、观察条件与停止标准。拒绝：自行设试单数量/预算或以样品一次合格保证全批次。

## 交付与验收

- `facts`：需求、来源、明确条件和未知项各自可追溯。 不通过情形：把供应商自述当独立核验。
- `normalizedQuotes`：实际采购量、超购量、到货总额和未计费用同口径。 不通过情形：只算需求数量乘单价，忽略MOQ。
- `constraints`：区分通过、排除和待确认及其依据。 不通过情形：把待确认条件写成通过。
- `comparison`：无权重多维比较，有统一口径才条件评分。 不通过情形：缺项重分权重或把未知质量计高分。
- `recommendations`：建议以条件表达，并明确最小验证及停止条件。 不通过情形：保证质量/交期或自动决定试单投入。
- `handoff`：交原始材料、实际回执或未执行说明及待决定项。 不通过情形：称已联系、下单、付款或已获最终批准。

## 正例与反例

以下是作者设计的合成片段，不是模型运行记录，也不是完整正式交付；预期判断仍需独立专业复核。

### moq-cost（可接受候选）

合成需求120个同规格袋，A最低150个每个2元另运费35；B恰好120个每个2.1元另运费23。

输入：{"specification":"相同布料尺寸拉链袋，单位个","quantity":120,"currency":"CNY","quotes":[{"supplier":"A","unitPrice":2,"moq":150,"shipping":35},{"supplier":"B","unitPrice":2.1,"moq":120,"shipping":23}]}

候选输出片段：

```json
{
  "normalizedQuotes": [
    "A需买150个，335元，超购30个。",
    "B需买120个，275元，无超购。"
  ],
  "recommendations": [
    "已知到货费用B较低；质量、交期和未计费用仍待确认，不能仅据此保证B最佳。"
  ]
}
```

判断理由：按真实购买量比较，并限定结论范围。

### unknown-fee（应拒绝候选）

A运费未知，B已含运费，未给质量权重。

输入：{"specification":"同规格袋","quantity":120,"currency":"CNY","quotes":[{"supplier":"A","unitPrice":2,"shipping":null},{"supplier":"B","unitPrice":2.1,"shipping":23}]}

候选输出片段：

```json
{
  "comparison": [
    "A运费按0元，默认质量90分，总分第一。"
  ]
}
```

判断理由：未知运费和质量不能变成零成本与虚构分数。

## 失败与人工边界

- 合同、进口税费或合规结论交相应合格人员确认；一般报价算术可继续。
- 用户决定采购投入和风险接受；任何联系、付款或订单动作另由宿主处理。
- 必要事实/能力缺失时交具体影响和下一步，不伪造执行；只停止受影响部分，整体调度由调用方决定。
- 专业效果状态是 `not_evaluated`；合同验证和资料完整字节交接只证明结构与来源运输，不能代替真实任务质量。
