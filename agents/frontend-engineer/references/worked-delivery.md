# 编辑表单的状态、并发和可观察验证

这是本包的原创合成工作样例，用于说明专业步骤、完整交付和拒收条件。它不是真实客户成果，也不是模型效果评测；实际任务替换输入与约束，按当前标准独立核验。

## 实务任务

合成任务：给现有订单页面增加备注编辑。服务端接口返回记录version，保存要求携带If-Match或等价版本条件，409/412表示冲突；具体字段以当前接口为准。交付应包含实现、行为证据和集成说明。

## 实施方法

1. 读取真实入口、组件、锁文件和API客户端。识别服务器记录、未保存草稿、保存请求三种状态；由现有状态层分别负责，避免多个Effect互相同步。
2. 用用户动作驱动保存，而非依赖渲染副作用触发写入。保存按钮的禁用只改善体验，服务端仍必须处理幂等与版本冲突。
3. 处理乱序：先发的查询晚返回时，不得覆盖用户之后编辑的草稿或更新的记录。取消请求不等同取消服务器写入，需按接口查询最终状态。
4. 保存成功只接受该次请求对应的当前结果。失败保留输入；冲突展示差异/重新加载选项，不能无限自动重试。
5. 从真实用户入口验证，再运行必要类型/构建/相关回归。没有浏览器时交可审补丁与未验证项，不能把截图路径预先填成证据。

## 最小行为验收表

| 场景 | 操作 | 合格观察 |
| --- | --- | --- |
| 正常保存 | 改备注并保存 | 记录更新一次，刷新后值一致 |
| 慢网络重复点击 | 连续触发两次保存 | 无重复业务记录，等待状态可理解 |
| 旧响应晚到 | A查询后触发B，B先返回 | 页面保持B对应状态，草稿不被A覆盖 |
| 服务端冲突 | 另一用户先保存新version | 显示冲突，保留草稿，要求当前版本下处理 |
| 网络/鉴权失效 | 保存时断网或返回401/403 | 不报成功；恢复路径清楚且不泄露数据 |
| 键盘与窄屏 | 只用键盘编辑/保存，查看错误 | 名称、焦点、错误关联和操作位置可用 |

## 控制响应与实际保存各证明什么

先在隔离会话用受控409验证“失败保留草稿”，结果只记为前端冲突处理。再在授权集成环境使用独立测试记录保存，等待页面成功反馈后重新读取该记录，核版本和值确实变化；这一步未运行就明确保存持久化仍未观察。

另一个反例：测试拦截PUT直接返回200，再把随后的GET也固定成期望内容，页面能展示新值，但真实服务器甚至可能从未收到请求。把这种结果写成“后端已保存且刷新可恢复”应拒收。mock覆盖范围必须跟证据一起交付。

## 交付组织

patch 引用实际变更文件与必要上下文；behaviorEvidence逐条绑定环境、输入、期望与观察；handoffNotes记录接口版本、回滚影响和剩余限制。任何演示数据都标合成。性能判断先测主要瓶颈，再决定拆包、缓存或并行读取；独立请求可并行，依赖身份/授权的请求不得抢跑。

## 变体与拒收

离线编辑需另定本地保存和冲突合并规则；自动保存需明确节流、失败重试和离开页面行为；批量编辑需给逐项结果。出现测试全绿但真实入口未连接、以删除失败分支修复测试、把前端鉴权当安全边界，都应退回。
