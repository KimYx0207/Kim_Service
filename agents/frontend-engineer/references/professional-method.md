# 前端工程知识装配

方法版本：0.2.0。适用于已选中 frontend-engineer 的当前任务；本页是包内原创方法，不代表本轮访问过外部网页。来源编号、固定修订及取舍见 ../PROVENANCE.md。工具授权、调度和最终接受仍由调用方管理。

## 先把输入变成可实现的事实

从指定代码入口和锁文件确认框架、路由器、状态库、组件库及测试工具的实际版本；区分声明版本、安装版本和无法核实的值。不要把 React 或 Next.js 当所有项目的默认栈，也不要为了符合参考项目重装框架。记录相关组件、接口调用方、状态所有者和已有回归测试，每项给文件路径与版本证据。

使用调用方 designBinding / designContext 对齐当前模块、已定决定和验收项。若接口尚未定，交回确切分歧，例如“409 是否包含最新版本”，不要自创另一套服务协议。无完整 PRD 的小修改可用当前明确契约；缺少影响实现的事实才报告阻塞。

## 实现方法与专业判断

1. 按用户动作画状态表：初始、加载、空结果、编辑、提交中、成功、失败、权限失效及恢复；只保留真实场景。每次转移说明数据保留、下一动作和可见反馈。
2. 区分服务事实、草稿和可计算显示值；已有数据可以计算出的值不再复制成第二份状态。请求返回须对应当前参数/版本，取消请求与忽略过期结果按所用框架选择，不能把旧响应覆盖新输入。[react-effects]
3. 并发读取只在互不依赖、预算允许时进行；有鉴权、事务或结果依赖就保留顺序。先测请求瀑布与包体，再决定优化；不引用上游倍数当本项目收益。[vercel-react]
4. 沿用项目视觉语言和语义组件；自绘控件要补键盘、可见焦点、名称和错误关联。涉及模态框时检验焦点进入、Tab 范围、Escape/取消和关闭后恢复；不能只加 aria-modal 属性。[w3c-dialog]
5. 小屏、长中文、空数据、错误状态也要布局正确。交互说明优先于装饰；新视觉方向先与 interaction-designer 的规格对齐，已有品牌与用户选择优先。[anthropic-frontend]
6. 改旧代码前搜索调用、动态加载、路由、构建脚本和测试。删除候选给替代项、无消费者的证据和恢复办法；搜不到静态引用不足以删除公开入口。

## 正例与反例：取消同步冲突

输入事实：本机草稿 B 基于版本 7；云端已到版本 8；接口只允许条件更新。用户点取消应回编辑且保留 B。

反例：把云端数据写回草稿再关闭弹层；按钮隐藏但旧请求仍能覆盖 B；测试只断言弹层消失。这会丢用户修改，即使类型检查通过也不合格。

正例：草稿与远端快照分别保存，取消只改变展示状态；保存失败保留草稿。先发旧请求再发新请求，故意让旧请求最后返回，断言仍显示最新选择；取消、返回、再次进入都逐字比较草稿。具体 API 和实现必须来自当前仓库，示例不是可复制的生产补丁。

## 实际验收和交付

| 检查 | 可接受证据 | 不足以证明 |
| --- | --- | --- |
| 状态与乱序 | 控制请求完成顺序的真实测试输出，含输入和期望值 | 代码里出现 AbortController |
| 交互恢复 | 浏览器实际操作记录、最终页面及草稿值 | 只有静态截图 |
| 键盘/响应式 | 指定视口的截图和焦点路径观察 | “支持无障碍”的自述 |
| 工程回归 | 最终补丁对应的类型、构建和适用测试退出码 | 改代码之前的通过记录 |
