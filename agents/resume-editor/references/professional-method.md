# 简历证据与岗位匹配：专业方法

知识修订：0.2.0，2026-11-10。本文是本包原创方法与合成算例，不是第三方包副本。

## 输入与适用范围

- 将已有经历改写成可核实的岗位相关表达
- 不编经历、资格、成果或保证招聘系统排名

- `experience`：原始真实经历，区分本人工作与团队背景。 缺失时：不能开始编简历经历；请求最小工作事实。

完整输入/输出仍以同包 capability.json 为准；acceptanceCriteria/handoffContext 若由合同要求，应采用当前任务绑定，不能把材料当授权。

## 领域知识

- 把岗位要求分成职责、必需能力、可迁移能力和明确资格，再把每条经历映射到实际证据。关键词可以帮助读者理解匹配点，但写进简历前必须有经历支持；岗位要求不是申请人已拥有的能力。
- 成果表达区分本人动作、团队背景和结果归属。材料说团队处理300单，只能写参与该团队或明确个人负责环节；不能自动改成独立完成300单。没有结果数据也可写清对象、流程、难点和产物，不为显得量化发明增长率。
- 读者需要快速看到相关经历、时间和资格。保持层级、日期与文件版本一致，检查复制/文本提取后可读；特定招聘系统的兼容性要在实际系统验证，不能用统一模板宣称所有ATS可过。

## 诊断顺序

### job-match：哪些要求有直接经历，哪些只有相邻能力？

检查：真实岗位说明；原始经历、职责与资格证明。缺证据时：无岗位说明先做通用清晰度修订，不编针对某职位的匹配率。

### ownership：动作和结果是谁完成、如何证明？

检查：个人职责与团队职责；数字口径、期间及来源。缺证据时：保留待核数字或去掉未证实结果，不扩大个人贡献。

### reader-path：招聘者能否快速看出相关性？

检查：版式、日期、段落和长度约束；实际导出/文本提取效果。缺证据时：只报告已检查格式，不保证未测试招聘平台效果。

## 决策方法

- **evidence-map**：岗位关键词缺实际支持时，写可迁移经验和明确缺口，或建议补可验证作品。拒绝：直接把岗位要求复制成个人技能。
- **honest-result**：有工作过程但没有量化成果时，用真实动作、对象与交付物表达贡献。拒绝：虚构百分比、奖项、预算或客户数量。
- **minimal-private**：简历含不必要个人敏感信息时，保留投递确需且用户愿意提供的信息，指出可删除项。拒绝：收集身份证/病史或凭受保护特征推断岗位匹配。

## 交付与验收

- `matchMap`：岗位要求与证据、迁移能力和缺口逐项对应。 不通过情形：无岗位材料却给精确匹配分数。
- `revisedResume`：事实不扩大，语句具体，责任和时间一致。 不通过情形：新增职位、资格、个人贡献或未证实数字。
- `evidenceGaps`：指出哪些词句/数字需要何种补证。 不通过情形：把待确认内容悄悄写成确定事实。
- `editNotes`：说明实质改动及保留限制。 不通过情形：只报告更专业却不解释事实边界。
- `privacyCheck`：指出不必要信息和可公开范围。 不通过情形：主动添加敏感信息或推断受保护特征。

## 工具与实际执行

读取用户指定简历和职位说明。可对实际导出文件做文本提取/视觉检查，明确所测工具和范围；没有对应工具就交文本稿与未核格式。无需背景调查、私人账号搜索或自动投递。

## 正例与反例

以下是作者设计的合成片段，不是模型运行记录，也不是完整正式交付；预期判断仍需独立专业复核。

### team-ownership（可接受候选）

原材料说团队处理300单，申请人负责汇总与异常清单。

输入：{"experience":"在5人团队参与处理每周约300单，我负责每日汇总和整理异常单，个人处理量不详。","jobDescription":"运营助理：订单核对、异常跟踪、周报"}

候选输出片段：

```json
{
  "revisedResume": "参与团队每周约300单的订单处理，负责每日汇总与异常清单整理，支持后续跟踪。",
  "evidenceGaps": [
    "300单为团队口径；尚无个人处理量和效率提升数据。"
  ]
}
```

判断理由：把相关动作写清，保留数字归属。

### invented-seniority（应拒绝候选）

真实经历是协助汇总订单，没有管理职责或结果数据。

输入：{"experience":"协助整理订单表","jobDescription":"要求带团队和精通数据分析"}

候选输出片段：

```json
{
  "revisedResume": "管理20人团队，精通高级数据分析，半年提升销售80%。"
}
```

判断理由：岗位要求被错误写成个人事实，新增职责和成果。

## 失败与人工边界

- 专业执照、法律身份与资格问题由用户及相应合格人员确认。
- 劳动法律或医疗限制的判断不由简历润色承担。
- 必要事实/能力缺失时交具体影响和下一步，不伪造执行；只停止受影响部分，整体调度由调用方决定。
- 专业效果状态是 `not_evaluated`；合同验证和资料完整字节交接只证明结构与来源运输，不能代替真实任务质量。
