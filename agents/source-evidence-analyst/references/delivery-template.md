# 专业交付模板与完整算例

## 研究/核查包模板

1. 问题与范围：声明ID、对象、期间、用途、预定纳排、版本。
2. 检索日志：来源/数据库、准确搜索式、实际日期、过滤、取得数、未执行项。
3. 材料去向：记录ID、重复于谁、是否寻获全文、排除原因、研究ID、纳入依据。
4. 证据矩阵：声明/研究、原始位置、设计/样本/结果口径、支持程度、局限和反证。
5. 综合：可支持判断、条件、冲突、替代解释、会改变决定的下一证据。
6. 完整任务交接：运行状态、产物、逐项标准、缺工具与未完成范围。

## 完整合成样例：搜索记录不是独立研究

研究问题是某工具是否减少给定任务耗时。事前只纳入相同任务定义、可识别比较组和报告观察期的材料；不要求结果必须正向。

查询Q1取得12条记录，Q2取得3条，共15条；去重4条后筛11条。标题/摘要排除4条，寻获全文目标7份；1份未取得，6份实际评阅。全文排除2份（任务定义不符、没有比较），纳入4份报告，其中两份来自同一研究，因此是3项独立研究，不是4次独立验证。

这组数应能对账：15−4=11，11−4=7，7−1=6，6−2=4。缺全文1份保留未取得与影响。若排除规则是在看结果后新加，需要披露变更并重查纳排。

研究A/B在明确场景报告耗时下降，C结果不一致。不给“全行业已证明提效”的结论；先列任务、人群、版本和指标差异，给“已取得三项研究在这些范围的结果”以及未取得材料可能影响。四份报告齐全或PRISMA式表格完备不证明偏倚风险已解决。

另一个平台通知例：只看到“附件缺失”，仍需提交编号、文件清单和上传回执，不能直接指控平台责任或声称已经申诉。

## 当前任务交接

按照同包capability.json保留完整输出和任务绑定。status只描述本角色；artifactRefs仅引用实际产物并注明设计/合成/本地/宿主等证据类型；criterionResults对每项标pass/fail/not_run/blocked及实际证据。缺工具进入missingCapabilities，真实失败进入failures，stopReason和handoff说明下一步和影响。nativeRuntimeVerified保持false，最终接受归调用方。

每条专业质量规则都应有当前产物位置、检查方法、证据、结果与未决项。未检查不能默认通过；作者算例不是独立验收。
