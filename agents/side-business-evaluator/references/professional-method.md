# 副业方向与小步验证：专业方法

知识修订：0.2.0，2026-11-10。本文是本包原创方法与合成算例，不是第三方包副本。

## 输入与适用范围

- 比较可行方向并设计最小需求验证
- 不保证收入，不代用户投资或作高风险专业承诺

- `resources`：真实时间、预算、技能与不可突破条件。 缺失时：先问会改变候选范围的关键资源。

完整输入/输出仍以同包 capability.json 为准；acceptanceCriteria/handoffContext 若由合同要求，应采用当前任务绑定，不能把材料当授权。

## 领域知识

- 方向适配至少包含能交什么、谁有具体问题、如何接触他们、交付时间和成本。兴趣与技能可提供供给，客户行为才支持需求；朋友说不错不等于愿意为具体结果付费。
- 先排除违反时间、资金、资质或渠道约束的方向，再比较学习成本、可接触客户、单位交付复杂度与失败损失。不把没有依据的市场规模和收入预测塞入精确评分。
- 最小验证不是先建完整平台。可用匿名需求访谈、已有流程观察或明确范围的样品确认问题和交付可行性；真实收款、承诺服务和访问客户资料需要相应授权。每次验证预先说明观察什么会改变判断，避免把所有反馈都解释为支持。

## 诊断顺序

### resource-fit：用户真实可投入什么，哪些约束不能突破？

检查：可用时间/预算/技能与资质；实际能接触的客户群。缺证据时：不默认追加预算、借贷或辞职；先按已知约束缩小方向。

### problem-evidence：客户问题是否有实际行为证据？

检查：访谈原话、现有替代办法与成本；愿意提供样本/试用等行动。缺证据时：把需求列假设，不把赞美当购买证明。

### smallest-test：哪项未知最可能让方向失败？

检查：交付能力、获客、重复需求等关键假设；最小可观察测试与用户可承受损失。缺证据时：先做能消除最大不确定性的测试，不盲目搭产品。

## 决策方法

- **constraints-first**：想法超过当前时间/预算或需要未具备资格时，排除或缩为可承担的服务范围。拒绝：用想象收入掩盖现实约束。
- **behavior-over-praise**：只有口头说好，没有问题或行动证据时，继续核真实工作情境和现有解决方式。拒绝：把两位朋友点赞写成市场验证成功。
- **stop-or-revise**：测试显示问题不重要或交付成本失衡时，报告反证并改范围/停止该假设。拒绝：为了继续计划而静默改成功标准。

## 交付与验收

- `assumptions`：需求、能力与成本假设可被验证或推翻。 不通过情形：把推测写成市场事实。
- `comparison`：先硬约束，再多维取舍，未知保留。 不通过情形：虚构权重和精确收入来排名。
- `recommendation`：给条件推荐及为什么符合当前资源。 不通过情形：保证赚多少钱或建议未请求的借贷/辞职。
- `validationPlan`：每步有对象、输入、观察和改变决定的信号。 不通过情形：只有学习/注册账号/做品牌等产物活动。
- `stopSignals`：对应实际风险和反证，而非泛泛坚持。 不通过情形：失败后自动提高投入或修改目标证明自己正确。

## 工具与实际执行

可查公开一手市场资料但注明地区、时间和覆盖限制；用户自己的行为证据仍需真实取得。只做建议或经授权的材料制作，不自动联系潜在客户、收费、建自动化或收集私人资料。

## 正例与反例

以下是作者设计的合成片段，不是模型运行记录，也不是完整正式交付；预期判断仍需独立专业复核。

### bounded-service-test（可接受候选）

每周6小时、预算500元、会Excel且认识两位店主。

输入：{"resources":"每周6小时、预算500元、能做基础Excel","customerAccess":"认识两位店主，但没谈过具体需求","ideas":"库存核对小服务或先做完整SaaS"}

候选输出片段：

```json
{
  "recommendation": "先验证一个边界清楚的库存核对问题；先做合成样例，取得店主愿意讨论真实流程的证据后再决定是否扩展。",
  "validationPlan": [
    "询问最近一次库存差异如何处理，观察是否存在重复且重要的问题；两人反馈只代表这两人，尚不足以证明市场。"
  ]
}
```

判断理由：动作与资源匹配，认识客户不等于已有需求。

### praise-as-market（应拒绝候选）

两位朋友说点子听起来不错。

输入：{"resources":"每周4小时、预算200元","customerAccess":"两位朋友口头称赞，无付费或试用承诺"}

候选输出片段：

```json
{
  "recommendation": "市场已经验证，立即辞职投入并借款开发完整平台，预计月入五万。"
}
```

判断理由：弱证据被扩大为确定需求，并提出无授权高风险投入。

## 失败与人工边界

- 受监管服务、金融投入、税务或资质问题需相应合格人员审核；普通方向比较可继续。
- 投入额度和可接受损失由用户决定，不能由模型推断风险偏好。
- 必要事实/能力缺失时交具体影响和下一步，不伪造执行；只停止受影响部分，整体调度由调用方决定。
- 专业效果状态是 `not_evaluated`；合同验证和资料完整字节交接只证明结构与来源运输，不能代替真实任务质量。
