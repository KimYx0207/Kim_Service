# 内容脚本与文章写作：专业方法

知识修订：0.4.0，2026-11-10。本文是本包原创方法与合成算例，不是第三方包副本。

## 输入与适用范围

- 按实际渠道写完整可用稿件
- 区分文章、口播和镜头脚本，保留用户立场与事实边界

- `topicAndAngle`：主题、立场和希望解决的读者问题。 缺失时：先交最小角度选择，不能替用户捏造核心立场。

完整输入/输出仍以同包 capability.json 为准；acceptanceCriteria/handoffContext 若由合同要求，应采用当前任务绑定，不能把材料当授权。

## 领域知识

- 先写出读者读完应理解或能做的一件事，再选结构。教程用问题—步骤—检查结果；解释文先展示矛盾或误区再给机制；经历文只能使用真实经历。结构服务论证，不把所有稿件套成同一三段口播。
- 每个事实句需要与材料一致的对象、范围、时间和条件；用户观点可以保留为观点，不能借引用包装成事实。数字算例可以原创但须标合成，不能写成客户成绩。引用能证明原作者说过，不一定证明其命题成立。
- 开头提出的承诺要在正文兑现，结尾让读者知道下一步或局限。口播时长受语言密度、停顿和镜头影响，字数只能估算；文章交完整段落而非镜头提示。拍摄可行性与文本质量是不同检查。

## 诊断顺序

### format-job：交付是文章、口播稿还是可拍镜头表？

检查：平台、形式、长度与读者任务；现有完整材料和作者语气。缺证据时：可用默认形式先交完整稿，并说明假设；只有交付形式会冲突时才问。

### claims：哪些句子来自材料，哪些是立场或推断？

检查：素材引用位置；数字、案例、因果和时效性声明。缺证据时：删减或改为条件表达，不补假的经历、成绩或引用。

### payoff：开头承诺如何在正文被兑现？

检查：段落/镜头对读者问题的贡献；行动步骤和结果检查。缺证据时：收窄开头或补实际解释，不用重复口号填篇幅。

## 决策方法

- **match-format**：用户请求长文或文章改写时，给可读完整正文，用论据和过渡组织段落。拒绝：只给分镜或把半分钟口播框架强加为全文。
- **evidence-first**：有吸引力的观点缺材料支持时，用可支持的具体结论；把立场/假设标清楚。拒绝：编数字、名人背书或个人亲历来增强说服力。
- **deliver-full**：所需材料足以写作且没有阻塞决定时，同时给开头备选、推荐及完整主稿。拒绝：让用户先选一个标题才继续本可完成的正文。

## 交付与验收

- `oneLiner`：一行说明稿件为读者解决什么。 不通过情形：泛概念无法对应正文结果。
- `hooks`：开头选项准确，正文能兑现。 不通过情形：用虚假冲突/数据骗取点击。
- `content`：按形式提供完整文章或可用脚本，事实范围准确。 不通过情形：只交提纲、断裂段落或未标明合成案例。
- `ending`：结尾连接正文结果与合理下一步。 不通过情形：突然添加不存在的产品承诺或强迫互动。
- `claimsCheck`：列真正需核的声明和对应材料/限制。 不通过情形：把自检清单全部打勾当事实已核实。

## 工具与实际执行

保留 AGENT.md 已有完整文章和口播示例。可读取指定材料；最新外部事实先核原始出处。没有录音/播放工具不能声称实际时长和口播顺畅已验证；视频生成、发布和商业承诺由宿主另行处理。

## 正例与反例

以下是作者设计的合成片段，不是模型运行记录，也不是完整正式交付；预期判断仍需独立专业复核。

### evidence-scope（可接受候选）

用户要写一段库存核对教程，只有合成练习表。

输入：{"topicAndAngle":"给新手解释Excel库存核对","format":"图文正文","materials":["合成示例：期初10，入库5，出库3"]}

候选输出片段：

```json
{
  "content": "先用合成练习核对：期初10件，加进货5件，再减出库3件，期末应为12件。若表中不是12，先检查是否漏记、重复或把数量写成金额。这只是演示检查方法，不能证明某家店已减少损失。",
  "claimsCheck": [
    {
      "claim": "期末12件",
      "status": "用户提供",
      "source": "合成输入10+5-3，可复算；非真实经营数据"
    }
  ]
}
```

判断理由：正文兑现教学承诺，合成数据未伪装真实成果。

### invented-result（应拒绝候选）

材料只有自己做的练习表，没有客户使用记录。

输入：{"topicAndAngle":"介绍自制库存表","format":"图文正文","materials":["没有真实客户结果"]}

候选输出片段：

```json
{
  "content": "我帮300家门店把损耗降低80%，这张表保证一个月回本。"
}
```

判断理由：编造客户、因果收益和保证；不能靠润色弥补证据缺失。

## 失败与人工边界

- 医疗、法律、金融以及有高影响后果的建议由相应专业人员审稿。
- 涉及真实客户/公司机密/他人私事时按用户明确授权范围使用。
- 必要事实/能力缺失时交具体影响和下一步，不伪造执行；只停止受影响部分，整体调度由调用方决定。
- 专业效果状态是 `not_evaluated`；合同验证和资料完整字节交接只证明结构与来源运输，不能代替真实任务质量。
