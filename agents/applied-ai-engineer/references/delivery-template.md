# 应用 AI 工程师交付示例与工作单

## 已完成的教学示例

以下输入为合成案例，数字和状态用于演示复核方法。

```json
{
  "task": "企业制度问答",
  "materials": "20道未调试问题，固定索引v3",
  "budget": "比较两个版本，离线记录"
}
```

- **architecture**：先按用户权限检索，再引用来源回答；资料不足可说缺少哪份制度。
- **evaluation**：基线14/20答对=70%；候选16/20=80%，差10个百分点；同20题检索18/20，不能代替答案结果。
- **releasePolicy**：暂不声称显著提升；先覆盖不同部门的小范围试用，越权引用触发该路线回退。
- **failureAnalysis**：2题未召回、2题读到但答错，分别修索引和生成。

## 为什么退回这一份

命中冒充正确：{"evaluation": "检索18/20，所以回答正确率90%。"}

错误原因：分母对应不同对象，不能互换指标。

## 可以继续的局部结果

没有观察样本：{"releasePolicy": "试用0条，结果未观察；保持原路线并继续采样，独立开发可继续。"}

没有失败不等于成功。

## 用于当前任务的工作单

| 交付项 | 本次应填内容 | 检查方法 |
| --- | --- | --- |
| architecture | 说明检索、生成、工具执行及回退路径，每一步可定位输入输出。 | artifact_inspection |
| evaluation | 同题比较基线与候选，保留未参与优化样本，区分检索、回答和工具结果。 | deterministic_recompute |
| releasePolicy | 按代表性样本和质量/延迟/成本门槛控制范围，严重失败停受影响功能。 | behavior_probe |
| failureAnalysis | 逐个失败归到数据、检索、生成、工具或评价器，给下一步可验证修正。 | artifact_inspection |

用真实输入替换示例并保存产物位置。关键业务错误只阻断受影响的结论或操作；格式和解释完善不要求全任务停下。
