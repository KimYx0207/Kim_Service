# 媒体制作与输出核验：专业方法

知识修订：0.2.0，2026-11-10。本文是本包原创方法与合成算例，不是第三方包副本。

## 输入与适用范围

- 给定授权素材的制作方案与实际产物检查
- 没有渲染能力时交可执行模板并标明未渲染

- `assets`：实际可用且获授权的素材及版本。 缺失时：交素材缺口，不下载或编造用户资产。
- `outputSpec`：媒体参数与可感知验收要求。 缺失时：先明确影响导出的关键项，保留其他待定。
- `workflow`：当前制作工具、项目文件和可用步骤。 缺失时：按模板交付，不声称环境已建立。

完整输入/输出仍以同包 capability.json 为准；acceptanceCriteria/handoffContext 若由合同要求，应采用当前任务绑定，不能把材料当授权。

## 领域知识

- 把输出要求分成容器、视频流、音频流、字幕与平台展示条件。文件扩展名不证明内部编码；画面宽高不必等于显示宽高，还需核像素宽高比与旋转信息。用户说“竖屏”并未自动指定帧率、HDR或响度目标。
- 时间线以明确时间基和帧率解释。变帧率素材不能只凭帧数推时长；声画开始偏移、剪点跳帧和重采样漂移需在实际输出检查。只看导出退出码不能确认字幕不遮字、对白清楚或音画同步。
- 先用最短代表片段验证最难部分：字幕、转场、色彩、音频及关键尺寸。扩到全片后重查实际输出，抽查起中末及风险剪点；抽样未覆盖的区段要保留限制。没有观看/收听能力不能写主观视觉与听感已通过。

## 诊断顺序

### spec-streams：用户要的文件与展示条件是什么？

检查：尺寸/比例/时长/帧率及音轨要求；目标平台与素材授权。缺证据时：区分必须项和未定项；无目标平台资料不编造平台限制。

### timeline：素材时间轴、音频和字幕有什么冲突？

检查：时码、帧率、声道/采样率；旋转、色彩标签与字幕位置。缺证据时：先交需要探测的字段，不用文件名猜参数。

### render-evidence：现在有真实导出，还是只有模板/命令？

检查：实际输出文件和工具回执；探测、观看、收听记录。缺证据时：只报告模板或未验证项，不列不存在的文件为成品。

## 决策方法

- **probe-before-fix**：导出参数与预期不一致时，用实际媒体探测定位容器/流/时长差异，再决定重封装或重编码。拒绝：未经检查统一重编码或把扩展名等同内部格式。
- **sample-first**：耗时渲染中有新的复杂环节时，先检验覆盖该环节的代表片段，再经宿主授权扩到全片。拒绝：用一张预览截图代替视频/音频验收。
- **separate-quality**：机器可读参数满足要求但感知检查未完成时，分开规格已核、视觉未核、音频未核与未覆盖区间。拒绝：把 ffprobe 或零退出码当审美、字幕与听感通过。

## 交付与验收

- `workflowPackage`：说明输入、版本、时间线、参数和复现步骤。 不通过情形：写通用命令却不标明当前环境未运行。
- `mediaArtifacts`：仅列实际文件，或明确空且仅模板交付。 不通过情形：把预计路径当存在的渲染产物。
- `qualityEvidence`：分别列参数核验、画面、字幕与音频实际检查。 不通过情形：将容器可读等同质量通过。

## 工具与实际执行

ffprobe 可读容器与流信息；用受宿主允许的本地文件参数，不把素材文件名拼为 shell 命令，也不因工具支持 URL 就扩展网络权限。保留已有 GPU/浏览器等租约交接规则；工具不存在时交未执行模板和精确缺口。

## 失败与人工边界

- 人物素材许可、敏感声音/肖像或版权争议需要用户及相应专业人员核实。
- 医疗、法律、金融宣传内容先由合格人员审核，不由渲染成功代替内容审核。
- 必要事实/能力缺失时交具体影响和下一步，不伪造执行；只停止受影响部分，整体调度由调用方决定。
- 专业效果状态是 `not_evaluated`；合同验证和资料完整字节交接只证明结构与来源运输，不能代替真实任务质量。
