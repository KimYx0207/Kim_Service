# 职场消息与决策沟通：专业方法

知识修订：0.2.0，2026-11-10。本文是本包原创方法与合成算例，不是第三方包副本。

## 输入与适用范围

- 根据工作事实写邮件/消息/汇报草稿
- 明确需要谁做什么，不替用户作未授权承诺

- `workFacts`：本次事实、阶段、责任和已确认时间。 缺失时：先收集最小状态事实，不代填进展。

完整输入/输出仍以同包 capability.json 为准；acceptanceCriteria/handoffContext 若由合同要求，应采用当前任务绑定，不能把材料当授权。

## 领域知识

- 先判断读者这次需要知道、决定还是行动。情况通知应突出变化及影响；请示要给可选路径、推荐依据和决定时点；任务交接要含对象、负责人、下一步与依赖。一个消息不必套满所有模板字段。
- 状态词需要事实标准：已完成、已提交、已批准、已上线不是同义词。对外方的预计时间保留主体和不确定性；“供应商预计明天发货”不能改成“明天保证到货”。
- 把可查事实、推断和请求拆开，语气可以调整但责任范围不能漂移。提及风险要具体说明影响和需要的决定；没有负责人或截止时点时说明待确认，不冒填他人承诺。

## 诊断顺序

### reader-action：这封消息要让谁采取哪种行动？

检查：收件人角色与沟通目的；用户希望的决定或下一步。缺证据时：先给可读草稿，只有目的改变表达时问关键问题。

### state-proof：每个状态词与时间点有什么事实依据？

检查：实际进展、批准与回执；外部估计的主体与条件。缺证据时：保留预计/待确认，不把草稿说成已提交。

### decision-clarity：对方需要哪些最小信息做决定？

检查：可选方案、成本/风险与截止条件；谁负责下一步。缺证据时：明确待定责任，不替收件人承诺。

## 决策方法

- **separate-status**：材料同时包含完成、待审和外部预计时，分别表述状态及其对下一步的影响。拒绝：把整体写成全部完成或保证如期。
- **ask-action**：消息目的是让负责人作选择时，给具体选项、推荐理由和不决定的影响。拒绝：只报问题却不写需要对方做什么。
- **keep-facts**：用户要求更强硬/更委婉语气时，改变措辞和顺序，保留真实责任与不确定性。拒绝：以语气优化为由增加指控、道歉责任或合同承诺。

## 交付与验收

- `messageDraft`：读者能看懂现状、影响和所需动作。 不通过情形：用长背景掩盖关键请求或夸大状态。
- `statusTable`：事实、预计与待确认分开。 不通过情形：把已提交当已批准。
- `actionRequests`：动作对象、负责人/待定与时点明确。 不通过情形：替他人承诺不属于其确认的动作。
- `unknowns`：缺口说明影响哪一项决定。 不通过情形：把事实未知伪装成泛泛风险提示。
- `toneNotes`：解释语气选择如何服务目的而不改事实。 不通过情形：为好听删掉对方做决定所需的限制。

## 工具与实际执行

读取用户指定事实与文档即可写草稿；无发送回执就不能写已通知。可引用当前文件版本，不扫描聊天历史或联系人以补隐私。实际发送、创建日程或替人确认由宿主按用户授权处理。

## 正例与反例

以下是作者设计的合成片段，不是模型运行记录，也不是完整正式交付；预期判断仍需独立专业复核。

### approval-state（可接受候选）

三份报价两份通过、一份待审，供应商预计明日发货而非到货。

输入：{"workFacts":"A、B报价已通过，C待经理审批；供应商预计明日发货，送达时间未确认。","recipient":"项目经理","request":"决定是否先用A、B推进"}

候选输出片段：

```json
{
  "messageDraft": "A、B报价已通过，C仍待审批。供应商预计明日发货，送达时间尚未确认。我建议先推进已批准部分；请确认是否采用此安排，并决定C是否需要补充材料。",
  "unknowns": [
    "送达时间未确认，影响整体到货计划。"
  ]
}
```

判断理由：批准与预期时间没有被扩大。

### promise-inflation（应拒绝候选）

材料只写供应商预计明天发货。

输入：{"workFacts":"供应商预计明天发货，尚无运单。","recipient":"客户"}

候选输出片段：

```json
{
  "messageDraft": "我们保证明天货物一定送达，所有事项已完成。"
}
```

判断理由：把第三方估计发货改成己方保证送达并虚构完成。

## 失败与人工边界

- 涉及法律责任、合同、雇佣争议或金融承诺时由相关人员复核具体措辞。
- 包含客户/员工信息的消息应按用户授权对象和必要范围使用。
- 必要事实/能力缺失时交具体影响和下一步，不伪造执行；只停止受影响部分，整体调度由调用方决定。
- 专业效果状态是 `not_evaluated`；合同验证和资料完整字节交接只证明结构与来源运输，不能代替真实任务质量。
