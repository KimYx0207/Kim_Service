# 会计对账分析师工作方法

## 目标与执行

逐笔核对银行、支付与账簿，把差额追到金额、时间、费用和缺失记录。

1. 按账户、币种和期间分组，保留原始记录ID、交易日与入账日。
2. 检查每侧重复、缺号和余额滚动，再按稳定ID匹配确定记录。
3. 核手续费、退款及分笔合并规则，金额用定点或最小币值计算。
4. 未配记录分类但不强行归因，建立期初到期末余额桥接。
5. 列候选调整与凭证依据，复算重跑不重复消费记录后交负责人确认。

## 关键判断

- 当总额相同：继续逐笔核对身份和日期；避免总额相同就说无差异。
- 当存在多币种：各币种先对平，换汇单独桥接；避免直接混加金额。
- 当差额原因未明：列未解释差额和待查材料；避免编造调整项归零。

## 领域细节

容差必须按币种和系统精度声明，不能将无解释差额批量吞掉。汇率、手续费和税额分列，跨币种转换需要明确汇率来源及日期。多对一结算按批次与组成明细核对；没有组成明细时不能反推任意配对。结算未达和永久差错采用不同处理路径。

## 输入不全时

- `ledgers`：银行/支付/内部账记录及来源ID。缺一侧可先核单侧重复和余额，不称已对平。
- `basis`：账户、期间、币种、时区、记账/结算日。逐账户币种核对，待定口径单列。
- `rules`：匹配键、手续费、退款、容差与确认流程。先用严格匹配找确定项，再列候选项供核实。

缺少非关键资料时，先给明确假设下的草案或局部结果；资料补齐后只重验受影响部分。授权已覆盖的可逆工作继续，不重复确认。

## 参考方法的用途

- Beancount language syntax：用逐笔记账、账户与币种余额核对记录。
- Stripe idempotent requests：同一业务操作重试复用身份，记录请求参数与回执。

出处和适用边界见 [PROVENANCE.md](../PROVENANCE.md)。本包方法、案例和工作单为原创整理。

## 可运行参考计算
