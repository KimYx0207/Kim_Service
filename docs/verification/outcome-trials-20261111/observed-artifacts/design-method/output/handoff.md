# 门店报名页交接 · v1.0.0

## 可直接使用的产物

双击同目录的 `index.html`，即可在现代浏览器中操作。保留这些文件的相对位置即可；无需安装依赖、启动服务或联网。页面使用本机系统字体、内联 SVG 和本地脚本。

| 文件 | 作用 |
| --- | --- |
| `index.html` | 页面结构、表单、原始示例和可访问名称 |
| `styles.css` | 布局、窄屏、焦点和组件状态 |

| `app.js` | 表单、名单、反馈、主题和焦点操作 |

| `verify.mjs` | 无依赖的静态、颜色数学与 Node 行为检查 |

## 操作方式

1. 打开 `index.html`，输入姓名和邮箱。可使用“王小明”和 `ming@example.test`。
2. 直接提交空表单会显示具体必填错误，并把焦点移到第一个错误字段。姓名支持中文、日文和其他文字，最多 100 个 UTF-16 字符单位；邮箱最多 254 个字符，进行基础格式校验，不验证地址是否存在。
3. 点击英文按钮，或在表单内按 Enter 提交。加载时按钮禁用、输入变为只读，状态模型也拒绝重复提交。待完成后，新增记录排在名单顶部，数量更新；成功反馈同时显示姓名和总数，表单清空并回到姓名输入。
4. 要演示恢复流程，先勾选“让下一次有效提交模拟失败”。校验不通过不会消耗该选项。有效提交后约 1 秒显示失败，名单不变，姓名和邮箱按原样保留；选项自动取消，直接重试会模拟成功。
5. 成功后的“查看刚加入的报名者”链接会滚动并聚焦新增行。仍可继续录入下一位。
6. 顶部主题按钮可以切换浅/深主题；首次打开时跟随系统偏好，手动选择仅本页有效。
7. 刷新页面可恢复初始演示。页面不提供真实导入、发送或保存。

## 组件规则与键盘路径

原生表单与原生按钮负责键盘交互，不拦截 Tab。正常顺序为：跳转到表单的链接 → 主题按钮 → 姓名 → 邮箱 → 提交 → 成功后才出现的查看链接 → 失败模拟复选框。可用 Shift+Tab 返回；复选框用空格切换。名单行默认不进入 Tab 顺序，仅“查看”链接可将焦点移到新增行。

| 组件 | 状态与规则 | 错误/恢复及名称 |
| --- | --- | --- |
| 输入框 | 默认、悬停、可见焦点、错误、加载只读；宽度随容器缩放 | 可见 label，required，hint/error 由 aria-describedby 关联；错误带 aria-invalid 和文字；校验失败与模拟失败均保留输入 |
| 主按钮 | 默认、悬停、按下、焦点、加载禁用；长英文允许多行，不固定文字高度 | 原生 submit；加载时 disabled + 状态模型双重防重；成功/失败后恢复 |
| 模拟开关 | 原生复选框；加载时禁用 | 只影响下一次通过校验的提交；失败后可直接重试 |
| 反馈 | 等待、加载、成功、失败；颜色之外有标题、符号与说明 | 常规反馈为 role=status / polite；错误摘要为 role=alert；校验错误聚焦字段，模拟失败聚焦摘要 |
| 名单 | 原始待确认、新增已加入、最新记录背景和程序焦点 | 语义列表、完整文本、独立状态文字；姓名/邮箱通过 textContent 写入 |
| 主题按钮 | 原生 button，两种主题 | 可见操作文案和 accessible name 同步更新 |

输入和按钮使用语义颜色；焦点环、边框和错误文字不依赖颜色反转。主要操作目标至少 44 CSS px；checkbox 的可点击 label 至少 44px 高。低动态偏好关闭旋转和过渡；强制颜色模式保留控件边界。

这些是实现规则与源码检查结果，**不是实际键盘或读屏器验收结论**。

## Tokens 与引用关系

变量分为原始值、语义角色、组件别名三层。每项有明确 `$type` 与 `$value`。主题分别绑定语义值，而组件保持相同名称。

| 引用层级 | 本页映射 |
| --- | --- |
| 原始值 | primitive.color.green700（浅）/ primitive.color.green200（深） |
| 语义角色 | semantic.color.action 引用对应主题原始值 |
| 组件别名 | component.button.primary.background 引用 semantic.color.action |
| 页面消费 | .primary-button 使用 --ds-button-primary-background |

例如浅色 `semantic.color.action` 指向 `primitive.color.green700`，深色指向 `primitive.color.green200`；按钮前景色分别使用白色和深绿文字。错误与成功同样独立定义前景、背景、边框。没有对整个页面使用 invert。

`tokens.json` 使用 typed token 的写法及自定义 theme 容器，不声称可直接导入所有 DTCG 工具。生成器拒绝缺失引用、类型不一致、循环引用和重复 CSS 名。布局断点为 820px 与 480px；这些规则也写在 tokens.json 的 `layoutRules` 中。

编辑变量后，在本目录运行：

```bash
node sync-tokens.mjs
node sync-tokens.mjs --check
node verify.mjs
```

页面运行不需要 Node；上述命令只用于编辑和校验。`verify.mjs` 会更新 `checks.json`。
