# 真实文件成果试跑与修正

本记录保留实际产物和失败，不把修复后的结果冒充首次成功。模型使用宿主继承的 GPT-6 Astra 独立上下文，没有启动付费模型 CLI。宿主未提供可比较的模型耗时或 token 计量，因此相关字段保持 null。

## 财务 v2

两组收到相同的合成输入、计算口径与格式要求；方法组另有 financial-modeler 0.2.0 的完整快照。输入、方法、题目、评分实现均在准备时冻结。独立复算脚本和结果另存于[`finance-v2/independent-review/`](finance-v2/independent-review/)；原评审中保留运行时的证据路径。各目录保存原始 task、run、input、output、grade、review；复制时逐文件核对哈希。

| 项目 | 基准组 | 带方法组 |
| --- | --- | --- |
| 三情景的36个月数值 | 独立复算一致 | 独立复算一致 |
| 已确认45元、待决定50元报价 | 正确保留 | 正确保留 |
| 利润和现金解释 | 独立审阅通过 | 独立审阅通过 |
| 50元报价敏感性 | 未做，明确说明 | 独立测算并复核通过 |
| 原始清单按消费者目录读取 | 可读 | 路径多了一层 output/，原始整体评分失败 |
| 原始评分 | task_pass | fail，未改写 |

两组基准全年净利润均为20,316元、年末现金16,954.50元、最大月末缺口2,137.50元。方法组单独计算的50元报价使基准净利润和年末现金各减少9,084元，缺口增加1,300元；这是本次观察到的补充内容，不是普遍效果提升证明。

路径差异也暴露题面没有把“相对哪个目录”写透。方法组明确声明其路径相对任务根，消费者实际约定相对output根。因此本次格式分数不能直接解释为专业数值能力差异。后续题目已给出双方相同的完整JSON示例，financial-modeler 0.2.1 将消费者路径与逐文件读取检查写入唯一验收步骤。

[`finance-v2/method-delivery-repair/`](finance-v2/method-delivery-repair/) 是宿主执行的单独交付修复：只修正submission的路径基准及三条路径，实际从output根读取全部三个文件；其他产物字节不变。`repair.json`记录前后哈希。它没有作为新的独立模型试验评分，也不计入首次成功率。

## 其他真实产物与浏览器观察

`observed-artifacts/`保存设计与前端续做的原始产物。设计交付为可编辑HTML/CSS/JS及tokens；前端续做保留原正文和行为，只修改指定标题。历史试跑没有冻结新版评分器，不补写为完整task_pass。

`tests/browser/outcome_trials.py`在GitHub Actions的真实Chromium中操作这些原始文件，保存窄屏、桌面截图和`outcome-trials.json`。若产物操作失败，观察记录如实写fail，不改模型答案。产品任务入口和两个官方样板另有必须通过的浏览器验收，二者不混为同一分数。

## 保留的无效先导试跑

[`invalid-pilot/`](invalid-pilot/)保留原财务题和产物。题目没有公开取整和部分字段要求，两组合理使用了不同口径，该轮分数不用于方法收益比较。只对该历史记录中机器路径做过的公开副本脱敏，均另存前后哈希；原件仍保留。v2的原始档案未改写。

## 结论范围

这是一组原创合成文件任务，审阅者为独立模型上下文，分组已知，不是外部盲审或会计审计。两组数值准确性没有观察到差异。方法组补充分析有用，但清单交付仍需修正。全部69个方法的`professionalEffect`继续为`not_evaluated`，不会因这次试跑改成已认证或最优。
