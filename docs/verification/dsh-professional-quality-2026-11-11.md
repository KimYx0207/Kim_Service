# DSh 与专业方法质量迭代记录

日期：2026-11-11（Asia/Shanghai）。这是主干源码迭代，未发布新的合集 Release，也没有作出“所有行业专家认证”的声明。

## 具体交付

基于 [研究与采用记录](../research/professional-expansion-2026-11-11.md)，新增 12 个专业 Agent、6 个 Skill，并改善原有 24 个 Agent 与9个 Skill。现有36个Agent、15个Skill都带专业方法和检查合同；另外保留1个Hook与1个Tool。自动目录共68项能力。404条输出检查、181个作者合成案例只是覆盖清单，不能当作业务成功率。

新增Agent覆盖经营财务、销售运营、用户研究、数据质量、应用安全、库存供应、制造质量、系统工程、招聘、碳核算、非临床医疗运营和农业水量；新增Skill覆盖实验分析、指标口径、SOP、需求追踪、建筑信息与游戏试玩。每包列出适用问题、输入缺口、领域推理步骤、完整交付样例、失败反例与工具边界。高风险内容限定到包内声明的分析范围。

旧包增加可复算或可逐项核对的完整交付：例如报价统一月份与费用、采购同时核MOQ与包装、经营指标明确买家/订单分母，软件设计包含状态、并发、失败和恢复。18份重复案例正文改为指向唯一案例文件与完整交付，保留原有工具、行业方法及许可。没有用短提示词替代原资料。

本轮另修正18个新包把诊断问题当作执行步骤的问题：诊断保留为输入检查，执行步骤按输入、动作、产物和失败处理编写。数据质量新增NULL覆盖、零检查行、同记录多错误等边界；前端区分模拟保存与真实持久化；需求追踪区分移动分支、固定源码和被覆盖的比较基线。算术及SQLite边界的独立复算见[复算记录](professional-boundary-recomputation-2026-11-11.json)。

## 每一项标准怎样衡量

沿用每包 `method.json` 的 `expertise.contractGuidance[].outputChecks`，没有另建质量总表。每条标准同时给出唯一ID、对应输出、通过条件、拒收条件、验证方法、必要证据和是否阻断。验证方法只能从产物检查、确定性复算、行为探针、来源核验与领域评审中选择。关键失败或缺证据不能用别项得分抵消。

默认检查所有正式专业包的完整合同；旧包兼容入口须显式声明 `--allow-legacy-quality`，保留 `legacy_incomplete`，不提升质量状态。入口使用16KiB上下文预算，不以60–130行文本长度判断专业能力。修复结构校验器按引用比较JSON数组/对象的错误，合法相同内容可以通过，不同内容仍拒绝。`uniqueItems` 进一步按JSON值判断重复，不受对象键顺序或内存引用影响；每项正式能力必须分别拥有合格与拒收样例，不能由同包另一能力代替。

Meta_Kim 将选中能力的标准与完整知识真正送到执行上下文，初态为 `not_observed` / `pending_independent_review`。工作者自报通过、安装成功、文件数量都不接受用户目标；现有宿主验收权威保持唯一。

制造质量包另增加零变差、单侧规格和负Cpk边界：无效参数不计算，单侧不补造规格，越界均值产生的负值保留；3个新增案例与26项包校验回归通过。它们证明规则与样例可检查，不能替代真实制造过程评估。

## DSh 的实现与边界

[使用指南](../dsh.md)说明构建、安装、更新、检查与卸载。构建器扫描正式能力目录，51个专业组件转换为原生Skills，保留完整方法、合同、工具、案例及许可。Markdown、JSON和可执行源码等长文本都有无损分段，不让工具结果裁剪丢掉后半部分标准。

真实DSh官方插件加载、读取裁剪、MCP及packed CLI生命周期证据由 [Meta_Kim的独立记录](https://github.com/KimYx0207/Meta_Kim/blob/main/docs/verification/dsh-native-host-20261111.json)承载。DSh适配没有把Skill冒充原生自定义Agent preset，没有声称原生硬Hook或模型业务验收。浏览器/电脑控制仍需宿主真实工具和授权，方法包不授予这些能力。
