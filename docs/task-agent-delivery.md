# 按任务组合专业交付团队

这批角色填补现有专业包缺口，不替换 Meta_Kim 的九个治理角色，也不新建 Service 排期器、权限系统或 provider 注册器。调用方使用已有 capability index 按任务选择角色。每个角色只读自己的入口、方法、当前任务材料与相关上游产物；不重复加载整个参考库。

## 责任与复用

| 任务形态 | 必要角色与依赖 | 主要交付 | 接受证据 |
|---|---|---|---|
| 产品与架构 | product-architect → interaction-designer / backend-data-engineer | 最小范围、状态、接口与迁移 | 用户结果到验收项；失败与回滚路径 |
| 前后端实现 | frontend-engineer 与 backend-data-engineer 在共同接口明确后并行 | 限定补丁、测试、版本与兼容说明 | 最终代码的类型/测试/构建；真实界面与服务另验 |
| 视觉与动效 | interaction-designer → frontend-engineer | 状态设计、token、动效与实现 | 真截图、键盘路径、reduced-motion、取消/返回 |
| 内容制作 | source-evidence-analyst → 现有 topic-planner / script-writer / headline-cover-optimizer | 来源包、成稿、标题封面 | 原始来源、事实归属、成稿和实际排版检查 |
| 媒体/数字人 | 现有 script-writer → media-production-engineer | 参数化流程、横竖版、音画与封面 | 实际导出、probe、抽帧和听检分别记录 |
| 量化研究 | quantitative-researcher → delivery-verifier | 数据/方法审计、回测材料与可复现包 | 时间因果、成本、样本外和真实回执；不接交易 |
| 平台/账号复盘、修订、只读资产清单 | source-evidence-analyst；写作按需复用 workplace-writer | 有来源的事实与人工交接材料 | 范围内实际读取证据；草稿与平台动作严格分开 |
| 课程资料 | 现有 lesson-planner / concept-tutor / exercise-designer | 课程、讲解、练习与更新依据 | 学习目标对应实际材料与练习；来源可追溯 |
| 商业化闭环 | 现有 side-business-evaluator → pricing-cost-analyst → launch-planner；按需复用 store-performance-analyst | 假设、成本、可执行试验、观察指标与复盘 | 实际可归因数据；不把计划写成已获收入 |
| 跨任务交付审查 | delivery-verifier | 清单、hash、确定性检查与缺口 | 本地工具回执；最终接受由调用方负责 |

角色不是固定人数。一个小修改可以仅用实现角色与独立验收；当前已完成的任务不重新创建。内容研究、写作、复盘等已有16个角色继续复用，避免再建同义角色。

## 执行合同

每个新方法包的 `capability.json` 定义领域输入输出，以及共享的：

- 输入：当前任务的验收条件、上游产物、已允许动作与资源租约；工具绑定含实际工具、版本、作用域、授权/回执引用及 available/missing/denied/unverified
- 输出：角色产物、逐项验收、缺失能力、失败动作与目标、停止原因、交接范围与待决定事项
- `method.json`：该角色的最小工具槽、按需技能、领域步骤、质量标准和停止条件；不包含具体账号、仓库、临时路径、固定片段数或用户任务清单
- `example.json`：完整合成输入输出，明确 partial / not_run；不是实际运行回执

默认 Agent 权限仍为 Read；方法中的写入、测试、渲染或平台槽是宿主需要满足的执行条件，不是新增权限。调用方需先实际发现工具、核实授权与作用域，再把真实工具绑定交给执行角色。工具不可用时交有用的设计/补丁/流程及缺口，不能冒充代码已经写入、视频已经渲染或平台已经发布。

Native Agent 加载、工具执行和最终用户结果是三个独立状态。新包保持 `needs_probe`。本轮的 Node helper 为显式宿主绑定入口，不自动进入 Meta 现有 Python calculation-delivery 路由。

## 共享资源与并行

此处规定交接要求，不实现另一套调度器。Meta 或调用方负责：

1. 在派发前固定输入版本、验收标准、授权边界和依赖；只有依赖产物已验证的分支才可执行
2. 每个共享浏览器会话、桌面前台、GPU设备和数据库迁移目标只能有一个有效写入/操作租约；纯读取可否共享由实际宿主决定
3. 获得资源前不导航、不键盘点击、不启动渲染；不能把“工具存在”当作持有租约
4. 交接时传递 resource、ownerTaskId、leaseRef；实际租约状态由宿主核实，提示词中的自声明不是有效锁
5. 失败、取消或退出时由宿主释放资源；没有可信释放回执则保留 blocked，不抢占或开第二实例
6. 工程前后端可在同一接口合同上并行，测试数据/代码隔离；媒体渲染与共用GPU的其他任务串行
7. 汇总只使用精确版本绑定的产物。冲突交回责任方修复，再重新验证，不混用旧通过与新代码

现包不执行资源锁，这些字段用于现宿主/治理层的交接。缺少可验证锁管理能力时明确报告缺口，不声称防止了跨进程竞争。

## 失败、停止与人工决策

- 缺输入：汇总真正阻塞的缺项；已能完成的范围继续，未回答不是批准
- 缺工具：给出需要的能力、影响、可用替代产物和最小下一步；不能把配置或安装当调用完成
- 明确拒绝：停止同目标，不更换API、终端、电脑、账号或Agent绕过
- 可恢复失败：仅在原授权内重试；出现新费用、生产变更、持久权限或新的外部收件人，交调用方确认
- 医疗、法律、金融高影响事项保留适用人工边界；研究不代交易、不保证收益
- 有些内容平台或本地环境不可进入时，角色交准备材料和人工步骤；不声称实际排版发布或本地写入成功
- `completed` 只覆盖列明的角色产物与已跑标准；仍有关键未验项时为 partial/blocked。最后是否满足用户结果由主控独立接受

## 可执行证据

`delivery-verifier` 的固定 Node helper 在显式授权根目录中实际读取文件，核对 manifest 的 bytes/hash，执行有限 JSON 值和回执绑定检查。它不执行任意命令，不把回执中的 passed 字样视为成功，不替宿主认证证据来源。人工、浏览器、模型与平台结果必须另验。

`quantitative-researcher` 的固定 Node helper 对显式收益、换手与费用做逐期净值和最大回撤计算，检查时间排序及信号早于执行。它不是策略回测引擎，不证明数据真实、价格可成交、样本外有效或未来盈利。

这些真实本地执行证明 helper 的有限作用，不证明全部角色完成原生宿主加载。领域步骤还需要实际任务中的工具、授权与外部验收。

### 租约等待、占用、释放与失效恢复

交接状态为 waiting → held → releasing → released；超时或执行者失联进入 expired / recovery_required。租约由宿主分配 taskId、leaseRef、generation 与 expiresAt，执行角色每次操作前必须由宿主确认仍有效。等待不操作资源，取消不自动争抢；收到释放回执才算释放。失效后先停止旧执行者并确认没有残留动作，再由宿主递增 generation 重新分配。若无法确认旧执行者已经停止，任务保持 blocked；不能仅因时间到了就启动第二个浏览器操作或GPU作业。当前组件只声明此交接协议，不宣称实现了跨进程 fencing。
