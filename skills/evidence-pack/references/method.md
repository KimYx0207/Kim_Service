# 大材料证据包 方法

## 判断顺序

1. 先固定公司、Work、材料版本和授权范围，读取 UTF-8 原文或已有提取结果。
2. 执行 build；保留完整 evidence-pack.json，原文仅分块保存一次，不静默截断。
3. 用 read 和分页游标取索引，再明确选择 chunkIds，在字节预算内装配上下文。
4. 将引用和剩余块交给当前模块；材料变化重新构建并核对哈希。

## 关键界限

来源、标题、页码和分块正文分开；保留追溯信息，再按需构建上下文。

不复制上游代码，不安装 OCR 或模型，不声明已提取 PDF 页面。

## 失败后恢复

来源字节变化后仍声称旧哈希有效，或将未读的块写成已读。 修正相关来源/版本后重跑本地 helper。每个输出包含完整输入与政策哈希；对超限材料明确分包，保留原文件，不静默裁剪。采用记录由调用方提供并绑定本次对象版本；脚本不能证明操作者真实身份。

## 与已有能力配合

原文分析交给 source-evidence-analyst；检索排名交给 retrieval-evaluation；产物字节与 Work 交接交给 delivery-verifier。保留各自职责，不能用本包的结构检查替代领域判断、最终采纳或真实运行回执。
