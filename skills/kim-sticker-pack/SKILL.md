# 先让角色和动作成立，再做表情包

为想把自己的角色变成常用聊天表达的创作者，交付身份稳定、动作能读懂、中文字清楚的动态贴纸。第一次必须读取 `references/production.md`，不得直接将图集送入旧版摆动脚本。

## 开始前：核实宿主工具，不把安装成功当成全流程能力

本技能使用标准 SKILL.md，可供 Codex 和 Claude Code 读取。先确认当前会话实际能否联网检索、查看图片、生成或编辑图片、制作动作素材、播放动画及运行 Python；名称或订阅不证明某项工具可用。Claude Code 不默认自带原生生图；Codex 当前会话也可能没有生图或视频工具。

没有生图工具时，停在研究、角色方案与提示词，等待用户提供已确认参考和动作素材，或在用户授权后接入实际可用服务。不得凭空声称生成完成，不自动开通服务、安装插件、调用付费API或消耗用户额度。没有动画播放能力时只报告帧与编码检查，视觉播放验收保持未完成。

相对路径均以本技能 SKILL.md 所在目录为根，不以用户项目工作目录猜路径。运行辅助脚本时使用该根目录下的实际文件路径；输入与输出则使用本任务明确路径。安装和双端调用见 README。

## 第一步：先研究同类经典案例，不凭空画主角

输入用户想做的角色方向与聊天用途，先搜索同类经典案例及当前常见聊天使用场景，优先找可查看原图/原动画的原作者或官方来源。浏览实际图片与动画，不只凭搜索摘要、名字、热度和印象下结论。

完成 `assets/case-study.md` 的证据与特征拆解：外形轮廓与识别点、表情幅度、动作预备和节奏、文字口气、使用对象与场景，各自为什么有效、有什么不适用处。至少覆盖有差异的方案，避免从一个样本复制整套视觉；案例数量由问题决定，不凑名单。

把能复用的机制与不能复制的角色IP分开。输出具体角色设计依据，例如轮廓可辨识、眼神可读、手势和短句匹配、适合小屏；不得照搬脸、服装组合、标志饰物或作者特有角色。附来源与权利限制，研究不等于获准改编或出售。

没有看见实际素材或关键来源不明时，列缺口并继续查可用来源，不假装完成研究后凭空生图。只有研究结论能解释下一步角色选择，才进入三视图。

## 第二步：按画面需要设计角色参考，等用户确认

输入研究结论、角色来源和使用目的。先写清拟采用的外形、表情潜力、动作能力及与参考的区别，核角色授权后再用宿主原生生图制作参考。用户明确要求三视图就给正面、侧面、背面，不能拿一张头像冒充；否则按下列规则选择，不机械增加无用视图。

- 全身卡通、精细二次元或涉及转身、背面与服装结构的动作，通常提供正侧背三视图，另保留脸部细节与色板。
- 真实人物以正脸近景聊天表情为主，先锁定基准脸，再补实际会用到的侧脸角度和表情参考，不必默认全身三视图。
- 真人要全身转身或从背面回头时，补对应全身视图和细节，不能用近景脸照证明衣着、体型或背面一致。

参考图是身份与设计依据，不是已完成动画。

服饰结构、头身比、发型、标志配件、左右细节必须能在三面对应。精细角色和写实人物保留原比例与材质，不自动Q版化。角色关键信息不明先研究，不凭印象抄一个热门IP。

把本路线所需参考图实际交给用户，等待对这一版本的明确确认，记录图片版本及对应消息。用户已明确确认的同一版不重复问，新增角色、重画脸型或改服装要重新确认。角色未确认时只能做角色方案，不能生成整套动作。

## 第三步：从聊天场景排文案与动作

输入已确认角色，输出 `assets/scene-plan.md` 的少量场景表。每条写谁在什么时候发给谁、2至6字准确文案、表情、姿态、动作弧线、静止背景、时间分配、落定与循环方式。

例如收到、好耶、困了是三种交流行为，不能分别给同一张图加不同摇摆。关掉文字仍应看出点头、欢呼和困倦，文字负责精确语气，不为错误动作圆场。

默认先选一条最容易看清角色与动作的样片，再做另外两条不同动作。不是先生成16格或100张，再给格子强行套文案。

## 第四步：按动作选择真实制作路线

有准确分层素材时，用关节枢轴和关键帧合成，保留遮挡关系，眼睑、手臂、头发只在各自合理范围运动。只用静态头部旋转不能冒充真实眨眼或嘴型变化。

有可用且已获费用授权的视频生成能力时，用已确认角色参考、固定镜头和一次明确动作生成，再检查身份、肢体、背景、动作节奏，裁取有效片段。工具名不保证身份一致或透明背景，没有实际工具返回不称生成成功。

只有连续姿势图时，先检查关键锚点和真实姿势变化，再统一比例对齐拼接。手型、面部、服装漂移就重做源帧，不能靠加速、光流或重复帧隐藏。低帧手绘风是明确风格选择，不强加给精细人物。

程序整体位移只可做辅助效果或用户明确选择的贴纸轻弹，不是默认主体动作。不得把整张桌子、床或人物一同正弦扭动，当成打字、入睡或挥手。

## 第五步：把文字作为美术设计，与动作一起创作

先读 `references/lettering.md`，按每条情绪、角色、动作、场景和构图设计字形、重音、倾斜/变形、配色、描边、层次、标点与位置。每张成品都必须有真实文字美术与画面整体设计，这不是可选加分项。不能所有表情统一工具字、统一上方或统一12度倾角，增加验收不能代替创作。

已有真实对齐连续帧时读取 `references/export.md`，用 `scripts/finish_frames.py` 合成字幕与分镜时长。该工具没有自然动作生成能力，源动作未成立时不能借它绕过返修。工具现已实际支持头顶文字、底部文字与可倾斜的前景叠字，并可配置共同人物区域和文字中心。它不识别人脸或手势，保护区须按实际帧标注；气泡与随动文字尚未实现。所有布局仍须实际播放验证。

精确中文可以通过手绘、矢量造型、原生生成文字美术层或字体二次处理完成，普通程序排字只是可选制作工具，只有经过本条字形、层次与构图的美术设计后才可进入成品，未经设计的默认工具字只能作草稿。生成文字须逐字核实，错误要返修，不可照收；文字的变形与时间变化由本条创意决定，不能意外跟随人体扭曲。位置不能默认塞在底部：先看人物动作的全时段包络、表情和手势焦点、画面负空间、读者先看哪里以及安全边距，再设计文字区域。

至少比较上方、侧方、下方或气泡中的适合方案，不要求每次凑全。文字可在任意经过设计的位置，可放头顶，也可在人物前方倾斜并适度压住身体，重叠本身不是失败。逐帧重点检查眼睛、表情焦点、关键手势及传达动作所必需的道具，非关键躯干和衣服可以根据构图适量覆盖；再检查运动路径与阅读节奏，不能只看首帧有空位；静止锚点优先，确需移动或分时出现时按动作节奏设计平滑路径，不能追着角色抖动。

文字长度不合适先调构图、位置或经用户同意精简，不缩到看不清。160px明暗底能读清是必要条件，文字与动作的整体关系仍须实际播放判断。

每条样片交实际动画、明暗底预览及160像素聊天显示尺寸。完整播放至少两轮，查动作预备、主动作、回弹与停留，查面孔与手指漂移、文字、裁切、色边、接缝。分镜图只能辅助，不能代替播放。

样片没通过就修这一条，不批量。向用户展示1至3条风格与动作不同的实际样片，等待明确认可后，记录确认版本再批量。只有角色确认不等于动作、字样和成品确认。

## 第六步：锁定后批量与交付

沿已确认角色、文案风格、动作强度和文字版式扩展。每条动作重新按语义设计，不复制同一时间曲线。数量不是成功条件，单条可用才可算成品。

交付按场景命名的GIF、保留透明的源帧/可编辑源、预览、权利说明、实际制作方式和缺口。技术核验仍检查帧数、周期、透明、容量与循环，但不能证明自然、好看、授权或用户满意。

## 停止与边界

- 权利不明不宣传可售，非商用角色只做允许范围内学习展示。代码许可不替代角色授权。
- 角色参考未确认、样片未确认、动作源不成立、字体缺字或无法实际播放时，停在相应阶段并明确缺口。
- 发布、付费、上传、改权限依用户具体授权，制作请求不自动授权上架。
- 不使用用户电脑或额度，除非明确要求。工具不足时交真实做到的部分，不换成纸片摆动后声称完成。
- 每个角色路线必须经过实际样片和用户认可才能声明可用。其它角色、写实路线、平台导入及销售并未因此自动验证。
