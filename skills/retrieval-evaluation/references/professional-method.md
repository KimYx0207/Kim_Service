# 检索质量评估工作方法

## 目标与执行

用独立标注和固定语料判断检索是否找到了相关材料，区分召回、排序与答案质量。

1. 固定问题、语料、权限范围和相关性定义，检查重复或泄漏标签。
2. 按相同k取得各版本有序结果，记录无结果和异常。
3. 逐题去重计算命中、召回及首个相关位置，再按约定聚合。
4. 分语言/任务/难度比较结果，回读失败文档定位原因。
5. 选择一个最可能原因做下一次试验，保持独立留出集不参与调参。

## 关键判断

- 当返回重复文档ID：只算一次命中但保留位置占用；避免重复命中增加召回。
- 当没有相关标签：召回记不可计算并报告数量；避免记完美召回。
- 当文档命中：另检回答引用和事实；避免宣称回答正确。

## 领域细节

不同工具的precision口径可能不同，本包示例固定P@k分母k，返回不足也保留空位；MRR取首个相关文档位置倒数。相关文档有粒度选择：原文、章节或chunk需统一，否则切块变多会改变标签含义。标注应检查无答案和权限不可见题。指标只度量所定义的检索对象。

## 输入不全时

- `dataset`：问题、相关文档ID、标注规则与留出划分。无标注先建设小型分层评价集。
- `runs`：相同语料版本下各查询返回的有序ID与分数。缺完整运行记录先按现有样本诊断。
- `policy`：k值、过滤权限、空结果处理及统计口径。先声明指标定义；无相关项单列不可计算。

缺少非关键资料时，先给明确假设下的草案或局部结果；资料补齐后只重验受影响部分。授权已覆盖的可逆工作继续，不重复确认。

## 参考方法的用途

- Ragas ID-based context recall：按独立相关文档ID计算检索覆盖，分开检索和回答质量。
- MLflow evaluation datasets and scorers：固定评价数据，保留已知失败与回归样本，比较同题版本。

出处和适用边界见 [PROVENANCE.md](../PROVENANCE.md)。本包方法、案例和工作单为原创整理。

## 可运行参考计算

本包提供 `scripts/score-retrieval.mjs`，以命名导出函数处理明确输入；运行 `node tests/calculation.test.mjs` 可复算本例和边界反例。它是局部参考算法，生产环境的权限、数据来源和完整业务路径仍按当前任务核验。
