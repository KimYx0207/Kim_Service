# 跨客户端离线评测：方法与判定准则

## 核心原则：为什么平均分不能直接决定上线

在多模型或多 Agent 客户端选型中，单一加权平均分最容易掩盖三类工程事故：
1. **分母漂移（Survivorship Bias）**：候选客户端在复杂长上下文案例上超时未返回，若只对成功返回子集算分，表面准确率反而虚高。
2. **底线击穿（Hard-Gate Violation）**：9 道普通问答各涨 2 分，但 1 道涉及越权泄露、金额错位或破坏性命令的红线题从通过变为失败——总分上涨但绝不可上线。
3. **切片退化与隐性成本膨胀（Slice Regression & Cost Blowup）**：简单题提升掩盖了核心付费场景退化，或准确率微升 1% 却伴随 P95 延迟翻 4 倍、单次调用成本超预算上限。

## 四维离线对比矩阵

| 评测维度 | 指标口径与核查公式 | 阻断 / 复核触发条件（Gate） |
|---|---|---|
| **1. 分母完整性** | `evaluatedCases + missingCases === totalFrozenCases`；逐题核对 `caseInputSha256` 与基线一致 | 输入哈希不一致拒绝横向排名；存在 `missingCases > 0` 时全集通过率按全量分母折算并单列缺失清单 |
| **2. 关键断言硬门禁** | 将断言分为普通质量项与 `critical: true` 硬门禁项（如 Schema 合法、无越权副作用、核心数值精确匹配） | 任意 `critical` 断言出现失败或从基线 `pass -> fail`，无论均分高低，禁止直接判定胜出 |
| **3. 逐题迁移与分层切片** | 统计 `improved`（败→成）、`regressed`（成→败）、`unchanged`，并按 `tags`（领域、语言、长度档位）聚合切片净收益 | 整体净收益为正，但某一核心业务切片净回归超过政策阈值时，标记切片退化告警 |
| **4. 成本与延迟帕累托** | 汇总实测 `cost` 与 `latencyMs`（均值、中位数、P95 及预算超限题数）；未上报回执保持 `null/unknown` | 严禁把未记录费用当作 `0` 参与性价比排序；超出 `policy.json` 预算上限时显式标记超支 |

## 判断顺序

1. **冻结基准**：锁定评测集案例、输入文本、确定性断言规则与切片标签，记录 `datasetSha256` 与每题 `caseInputSha256`。
2. **载入真实运行产物**：收集各客户端（如 Claude Code、Codex、Cursor 或不同模型配置）在同一基准上已产出的实际结果与计量回执，未知字段原样保留。
3. **运行确定性比对**：执行 `node scripts/run.mjs --input-json -`，逐题输出断言结果、基线迁移方向（升/降/平）、切片汇总与预算核查。
4. **人工复核边界题**：针对确定性规则无法完全覆盖的开放式表达或平局案例，抽取 `regressed` 与争议样本交领域评审或调用方决定是否采纳。

## 安全与工程边界

- **断言沙箱安全**：仅执行声明式确定性断言（精确匹配、子串/正则约束、数值容差、字段结构与 JSON 路径校验），严禁 `eval` 或动态执行用户提交的任意 JS/Python 脚本断言。
- **价格中立**：模型计费单价随供应商与企业折扣频繁变动，本包只核对运行回执中传入的实测费用或 Token 用量，不内置静态价格表猜测账单。

## 失败后恢复与协同分工

- 当发现某客户端因测试环境故障导致批量缺失或输入版本错位时，修正对应批次产物后重跑本地 helper；每次输出均绑定 `inputSha256` 与 `policySha256` 以便审计溯源。
- 对超出单包容量上限的大规模评测集，按切片或分片批次独立运行并保留原文件引用，不静默截断尾部样本。
- **职责协同**：原文事实核查交给 `source-evidence-analyst`；RAG 召回排序指标（Recall@K / MRR / nDCG）交给 `retrieval-evaluation`；最终交付物字节与交接核验交给 `delivery-verifier`。来源与许可证说明见 [PROVENANCE.md](../PROVENANCE.md)。
