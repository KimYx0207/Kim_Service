# 分阶段架构与流程图解：构图与校验方法

## 为什么工程与创作者图解必须使用“同源确定性布局”

用文生图模型画架构图常出现拼写乱码、箭头指错方向且无法局部改字；而纯手写 HTML 演示页又容易出现 SVG 图与旁边讲解词脱节。本方法要求**单一 JSON 图规格同时驱动静态 SVG、分步交互页与无障碍文本**。

## 构图与拓扑硬约束矩阵

| 设计维度 | 确定性规则 | 拦截的典型坏图（Anti-Patterns） |
|---|---|---|
| **单层认知负荷上限** | 每个阶段（Stage）并排节点数严格 `<= 5`；超出时必须按职责拆分为上下相邻子阶段 | 单排塞入 7~10 个方框导致字号缩到无法辨认或移动端横向溢出 |
| **首尾中轴锚定** | 起始入口节点与最终结果节点锁定在同一水平中心坐标（如 `x = 680`），建立清晰视觉阅读主干 | 起点偏左、终点偏右，读者视线在画布上无序折返 |
| **同层连线防横穿** | 同一阶段内横向连线仅允许连接相邻节点；跨节点依赖必须拆层表达 | 横向直线直接穿过中间无关节点卡片文字 |
| **退回路径外侧走廊（Return Gutter）** | 向上游阶段的回退/重试路径必须显式声明 `kind: "return"`，统一走画布左侧外走廊并纵向旋转标注文字 | 回退箭头穿过中间多层卡片造成网状交叉，或把逆向回退伪装成正向流转 |
| **节点与边语义着色** | 区分 `input`、`action`、`decision`（分支判断）与 `result`，边区分 `flow`、`decision` 与 `return` | 所有框与箭头同色同形，读者分不清正常主链路与失败补偿分支 |

## 交互演示与无障碍规范（`storyboard.html`）

1. **分步聚光灯讲解**：支持“上一阶段 / 下一阶段 / 显示全图 / 自动播放”，当前阶段高亮展示并同步切换右侧阶段说明与出处引用，其余阶段降噪半透明处理，适合技术评审、课程录屏与图文拆解。
2. **键盘与无脚本降级**：内置左右方向键（`ArrowLeft` / `ArrowRight`）切换，同时提供 `<noscript>` 静态全图回退，不依赖任何外部 CDN 字体或脚本。
3. **尊重动态减弱偏好**：自动检测系统 `prefers-reduced-motion: reduce`，开启时禁用自动轮播定时器，改为纯手动单步切换。
4. **防注入转义**：所有来自材料的标题、节点标签与阶段说明均经严格 HTML/XML 实体与 JSON Unicode 转义（如 `\u003c`），杜绝恶意文本变成可执行脚本。

## 四步标准作业流程

1. **抽象与核实**：阅读源代码或文档，提炼核心阶段（建议 `3 ~ 6` 个阶段），核实每条分支条件与失败回退目标与真实逻辑一致。
2. **结构校验与生成**：构造符合 `schemas/input.schema.json` 的图规格，运行 `node scripts/run.mjs --input-json -` 一次性产出 `diagram.svg`、`storyboard.html` 与 `walkthrough.md`。
3. **渲染状态诚实标注**：脚本完成后默认 `renderingObserved: "not_browser_verified"` 且 `runtimeStatus: "illustration_only"`；仅当宿主实际用浏览器打开核验像素无遮挡后才可在交接说明中补充浏览器观察记录。
4. **局部迭代与协同**：原文取证交给 `source-evidence-analyst`，需要交互式组件设计令牌时配合 `design-system-designer`，产物完整性核验交给 `delivery-verifier`。来源与许可证见 [PROVENANCE.md](../PROVENANCE.md)。
