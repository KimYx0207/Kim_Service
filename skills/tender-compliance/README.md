# 招投标证据与响应矩阵

把一叠招标文件变成带出处的响应矩阵，先找资格、硬性条款和失效证据，再整理可以完成的投标草稿。

## 使用

读取[专业方法](references/professional-method.md)与[交付模板](references/delivery-template.md)，按 `method.json` 顺序处理实际材料。

```sh
node skills/tender-compliance/scripts/run.mjs --input-json - < skills/tender-compliance/examples/input.json
```

该示例是合成数据。替换输入时保持单位、身份和版本一致。脚本从 stdin 读取 JSON，stdout 返回一个带输入/规则哈希的回执；没有网络、付费模型调用或业务写入。脚本输出需配合领域说明，不能当成全部专业判断。完整机器结构见 `capability.json`，示例期望和反例见[案例](evals/professional-cases.json)。

## 工作顺序

1. 按招标ID/标包整理正式文件与补遗，建立条款ID、当前版本和页段定位，拆强制与评分条件。
2. 逐条绑定响应章节与证据ID；对证照核主体、范围、有效日期和必要签章，不从其他项目借用结论。
3. 运行helper检查遗漏、版本漂移、过期、截止和未知条款；人工打开文件验证内容与给定哈希。
4. 把强制缺口和一般待补项分开，明确材料负责人及在截止前可完成的动作，不擅自提交澄清。
5. 交可编辑响应矩阵、证据索引、已知不符合与待审核事项；正式签署/提交仍由现有负责人处理。

## 交付与判断

每个条款保留原文定位与当前版本，响应逐一对应；版本落后、缺响应、缺引用、过期证据和明确不符合必须分开报告；强制项不能被其他得分抵消。

强制条款有缺口、截止已到、未知响应条款或任一响应未完成时needs_review；即使completed，readiness也只到ready_for_content_review，legalCompliance仍为not_determined。

## 范围

- 不判断特定辖区法律效力或保证投标合规/中标；以实际招标文件与当前规则为准。
- 不把有附件当成内容满足，脚本不读取或认证附件真实性。
- 不自动提交投标、联系评委、伪造资质或修改签章。

正式提交、签署承诺、价格决定和法律争议交现有投标负责人或相应专业人员审核；资料整理不新增审批。 普通可逆的读取、复算与草稿编制直接按当前任务授权推进。`needs_probe` 表示宿主未认证，不意味着本地脚本不可运行。包保留完整目录即可独立运行；复制入口一份不会携带资料。
