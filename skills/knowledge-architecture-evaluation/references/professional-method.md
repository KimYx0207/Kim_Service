# 按知识任务选择机制

## 先澄清对象

RAG 在查询时取证；LLM Wiki 将来源持续编纂成概念、实体、关联与综述；KV cache 复用模型上下文计算，CAG 把有界资料预载并缓存。图谱属于组织/检索结构，Agentic retrieval 属于查询规划与补证策略。这些层次可以组合，不能凭名词选一个万能赢家。

先取真实资料和任务分布：精确型号/错误码、事实定位、跨文档综合、全库趋势、长期积累各占什么位置；来源语言、扫描表格/图像、版本冲突、更新率、权限粒度、撤回时限、部署和预算怎样约束。段落数不能代替 token 数、信息密度和内存测量。私人研究笔记与多部门企业支持资料不能套同一默认值。

## 候选与适用反例

| 机制 | 适合检验的任务 | 必须排查的代价或反例 |
|---|---|---|
| 关键词、向量或混合 RAG | 精确术语与同义问法并存，动态资料和可定位证据 | 单向量漏标识、关键词漏改写；重排与混合增加成本，测收益再加 |
| 长上下文/CAG | 资料范围有界、相对稳定、重复问答多 | 上下文/显存、长文质量、缓存命中、失效与模型/tokenizer/缓存兼容 |
| LLM Wiki | 长期跨文档研究、观点积累和内容复用 | 编纂遗漏/错误传播、混合权限、派生撤回、浏览多轮成本与原文引用 |
| GraphRAG/LightRAG | 关系推理、整体主题与社区总结 | 图抽取噪声、语言支持、索引/更新/重建成本及关系来源 |
| 分解/Agentic retrieval | 多条件、多跳、需要补查的问题 | 额外模型与检索轮次、时延、预算及停止条件；简单事实不必多轮 |

企业动态权限语料先把可过滤的原文检索设为对照，再按失败切片试增强；这不是预判最终胜者。个人持续研究可优先试 Wiki+原始材料+搜索。图谱、Wiki、缓存都要有可观察增益才加入，维护负担不能由漂亮效果图忽略。

## 研究与版本

每个主张保留官方/作者 URL、读到的版本与日期、实验任务、真实模型和环境、局限、对当前决定的作用。除 README 外，查实际实现/依赖锁、迁移、更新删除与已知问题；不要把 workspace 隔离自动等同逐用户逐文档 ACL。

具体实例揭示检查方法，不能固化成永远正确的选型：CAG 作者明确要求相关资料放进上下文；GraphRAG 标准和 Fast 方法的抽取成本与图质量不同；LightRAG 按文档删除涉及共有实体重建；Microsoft llmwiki 删除单一来源派生页而保留多来源页，不能据此保证所有残留事实已清理。用安装版本重新核这些行为。

作者的 Wiki/RAG 对照在 v3 修复自动评分截断并加入人工校验，原先引用支撑优势不再成立；该研究只覆盖 24 篇论文、13 题和特定模型。它说明要分别评综合、引用和成本，不证明哪条路线普遍胜出。来源表标明修订，实际任务仍需自己的对照。

## 原文与派生知识生命周期

原文保留稳定 ID、版本、可追溯位置和访问规则；切块、摘要、Wiki、图关系、缓存记录到原文的依赖。编纂结果不替代事实源。更新来源时定位受影响节点，重建或标失效；撤回时禁止继续从旧派生内容回答；共有摘要不能因为还引用别的来源就自动视为干净。

检索、生成上下文、图遍历、引用、查询缓存都需服从当前身份与数据权限。权限变更时更新过滤和缓存策略，避免跨身份共享不相容上下文；实际执行用当前系统授权，不凭本包判断授予访问。缓存应绑定来源/策略版本和身份范围，不能只按问题字符串命中。

设计真实回放：来源修订后旧断言消失；撤回后检索、派生页与缓存都不再暴露；跨部门同题只见各自允许内容；中断重建后能恢复或明确拒绝过期结果。记录发生时间、完成时间、影响范围和完整暴露路径。helper 只能核给定快照，不能证明线上删除或权限执行发生。

## 质量、成本与比较

问题集按事实/术语/综合/关系/无答案/冲突/更新/权限分层，包含未参与开发的题。以当前原文逐断言核引用支持，区分检索命中、答案正确、引用支持、覆盖不足与拒答。自动评分器须与独立人工判断校准，保留分歧与失败样本；有引用不等于支持该结论。

固定语料、身份、模型、预算和允许变动的因素；报告索引与更新成本、每问 tokens/费用、冷暖缓存、p50/p95 延迟、存储、人工维护。用户质量底线、权限和撤回先判，不能被平均综合分抵消。按有限轮次和收益停止补证；未拿到数据时给试验设计，不虚构运行分数。

## 项目专业能力交接

每个长期项目从全局专业基底形成独立能力与规则。`projectCapabilityRequirements` 使用 `projectId/baseComponentId/baseComponentVersion/role/domainEvidenceRefs/responsibilities/boundaries/projectDelta/reuseConditions/targetPath/requiredInputs/toolRequirements/acceptance`。例如本项目的知识工程师带型号词表、来源与版本合同、ACL/撤回逻辑、题集和成本门槛；个人研究项目则突出观点冲突、来源追溯与综述复用。不得只换 Agent 名称。

已有项目包应保留定制并原地迭代，明确上游基底版本与差异；创建结果、hash、实际加载和独立评审由调用方现有机制承接。与 `technology-option-evaluation` 分工：该包比较通用版本/成本/替代机制，本包负责知识组织、取证与生命周期的专项判断；与 `retrieval-evaluation` 分工：后者复算检索指标，不能替代答案和架构验收。
