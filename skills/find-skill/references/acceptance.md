# 能力发现与安装验收

## 候选判读

候选表应回答五件事：它能产出本任务需要的什么；缺什么输入；会读写/执行什么；为何优于已有能力；哪里不能做。读取真实入口后，继续追到即将运行的脚本与外部调用。项目星数、搜索排序和“expert”措辞只帮助召回，不能代替审查。来源记录用仓库、技能目录、提交或版本、检查日期和许可证；没有核实的字段明确 unknown。

## 最小完整交付示例

合成搜索任务：在禁止外网的项目中找 CSV 字段检查器。本地 project/skills/csv-check/SKILL.md 描述了缺失字段检查和 JSON 报告，脚本只读指定 CSV。交付 localMatches=[csv-check，入口路径，必需输入 CSV+字段表，覆盖缺失字段，不覆盖业务语义]；externalSearchStatus=not-requested；candidates=[]。下一步可在当前任务许可内使用本地能力，不能推荐另装同功能包。这个示例不声称仓库自带该虚构技能。

安装示例：已核候选 reviewed-owner/csv-tools@reviewed-revision，精确 Skill csv-check，agent=codex。项目命令需明确 --skill csv-check -a codex，用户级才加 -g；示例来源是教学占位，实际执行必须换成已检查的真实来源。只获项目授权时失败也不能改用户级。安装报告完整包含 status、scope、verification：目标入口和所有被引用资源确实存在，来源版本一致，差异仅落在授权目录；宿主发现未观察则直说。用户级相同，但额外核验它影响该用户所有项目，不能把路径隐藏在“已安装”三个字里。

Windows 先核实当前 npx/Node/CLI 与 shell；PowerShell 是可选兼容路线，不能断言每个 Git Bash 都失败。英文词通常有助于跨语言召回，但中文零结果不证明后端只支持英文。只有搜索完成且输出可解释，才可报告本轮未发现合适候选。

## 反例与拒收

网络超时后报告“没有技能”；未读远程脚本即安装；仅列表里出现名字便说宿主已经运行；安装一个名字却把整个仓库所有技能装进所有 agents；项目失败后偷偷加 -g——都应拒收。恢复时保留已完成检查，纠正失败来源，不重复询问已明确给过的授权。

## 实际检查

发现检查靠入口/脚本/许可证回读；安装检查靠目标文件与源版本差异；触发检查必须是新的宿主实际观察。三者分开。此包不执行安装器，也不保证某个 CLI 版本支持文档中的所有选项，现场 --help 与批准命令优先。

## 加载与评估边界

执行本能力时按 SKILL.md 读取本文件及 method.json 中当前 capabilityId 的诊断、决策与 outputChecks。使用已有脚本和引用资料，不另造调度或运行状态。每条 blocking 规则缺证据或失败时保持未验收；其他高分不能抵消。作者自报 pass 最多是待独立复核的线索。

本仓库校验器验证合同、引用和示例格式；professionalEffect=not_evaluated。professional-cases.json 是作者合成的教学正反例，没有真实运行或人审发生性。当前 Meta 的 Skill 发现路径不会像 Agent 方法投影一样自动把 method.json 注入 worker；实际加载依赖入口的明确阅读规则和宿主支持，未观察则如实报告。原生宿主是否触发、业务效果是否改善，都必须另取当前版本的实际任务证据。
