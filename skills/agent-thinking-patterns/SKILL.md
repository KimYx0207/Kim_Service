# 跨 Agent 通用思考与行动方法

这是**所有专业 Agent** 可共享的可选方法层。当前 Agent 仍对自己的专业知识、实际操作和最终交付负责；宿主保持任务边界、权限、状态、审批与验收权。不要为使用本 Skill 新建项目状态机或覆盖已经决定的路线。

## 使用

1. **先做本职工作**：理解目标、现有材料、专业规则、可调用工具和当前授权。已有足够证据直接完成任务时，立即完成。
2. **按需选方法**：读取 [十种方法的唯一清单](references/patterns.json)，只挑能解决本次真实不确定性的模式。可以选一种、多种或者不选；不要固定套十问、十步或固定方案数量。
3. **结合专业方法实际执行**：把选中的质疑、比较、研究或练习机制嵌进本 Agent 原有步骤，保持统一事项和证据身份。不是重新分配角色，也不是把行业 Agent 变成通用顾问。
4. **保留真实边界**：问题已解决不继续提问；外部事实必须核源；没有证据就标未知；已提出的方案不等于人类批准或执行成功。
5. **回到用户目标**：最终输出可使用的结论、作品、决策或下一次动作，以及只有必要时才展示的依据和未核验项。

## 先练—提交—反馈不属于教育 Agent 专有

任何专业 Agent 在用户明确要学习、练习、复核自己作品或提升操作能力时，都可以采用 `practice-feedback`：

- **代码评审**：给一段真实但有界的重构任务，等用户提交修改，再指出哪条测试或设计边界没有满足。
- **产品设计**：让用户先画关键路径或 PRD 模块，等提交后按需求、依赖和验收依据给具体反馈。
- **销售、运营、投放、财务分析**：让用户先完成真实的小练习，提交可检查的内容后再解释错因和迁移条件。
- **教育 Agent**：在公共方法之上保留专门的题目与答案隔离、评分量表和教学顺序；这不是方法的唯一归属。

用户未提交时只返回待提交任务，不能编造已经批改或学会的结果。用户要求直接交付、生产修复或紧急处理时，不故意扣答案要求练习。

## 原方法、宿主与权限

已有专业 Agent 的 `method.json` / 资料 / 案例是领域能力来源；此处只补横向思考方式。宿主按其真实能力发现并按需加载此 Skill；目录存在、合同通过或 Catalog 收录，不表示已在 Claude、Codex、Gemini、DSH 或 ZCode 上自动注入成功。

用户授权与宿主权限不会因为调用公共方法而扩大；对外发消息、下单、发布、改配置或创建自动化，仍需本次实际授权和执行回执。参照 [专业方法与验收](references/professional-method.md) 以及 [method.json](method.json)；对于用户未给出的材料，保持 `not_run` / `evidence_required`，不自报已验证。
