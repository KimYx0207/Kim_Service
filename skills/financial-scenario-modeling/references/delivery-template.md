# 财务情景与压力分析交付示例与工作单

## 已完成的教学示例

以下输入为合成案例，数字和状态用于演示复核方法。

```json
{
  "baseline": "期初10000，5日付12000，10日收8000",
  "drivers": "收款可能延迟",
  "constraints": "最低现金0元"
}
```

- **scenarioInputs**：同月CNY，所有日期均为本例假设。
- **cashTimeline**：5日余额−2000，10日6000；最早缺口5日2000元。
- **sensitivity**：收款延迟使负余额持续更久；不能因月末6000而说全月可支付。
- **options**：比较经授权延期部分付款或提前回款，先核真实到账可能性。

## 为什么退回这一份

期末遮盖缺口：{"cashTimeline": "10000−12000+8000=6000，全月无风险。"}

错误原因：漏掉支付先于收款的中途缺口。

## 可以继续的局部结果

不完整输入继续结构：{"scenarioInputs": "缺到账日期时先列5日前/后到账两支，显示各支结果并待核日期。"}

局部未知可用情景表达。

## 用于当前任务的工作单

| 交付项 | 本次应填内容 | 检查方法 |
| --- | --- | --- |
| scenarioInputs | 基准、下行与变化来源清楚，币种期间单位一致。 | source_check |
| cashTimeline | 按真实收付先后定位最低余额和首次缺口。 | deterministic_recompute |
| sensitivity | 一次改一个变量做敏感性，情景联动另外说明；NPV时点明确。 | deterministic_recompute |
| options | 给影响具体缺口的可逆选项和复核点。 | artifact_inspection |

用真实输入替换示例并保存产物位置。关键业务错误只阻断受影响的结论或操作；格式和解释完善不要求全任务停下。
