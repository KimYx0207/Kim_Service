# 财务情景与压力分析

把不确定经营条件变成可调整情景，定位现金缺口与改变结论的关键假设。

## 输入与开始方式

- `baseline`：期初现金和按日期列出的收付款。可先交现金流结构，未知到账不能当已收。
- `drivers`：变化因素、范围、依赖和币种。标明独立敏感性与联动情景。
- `constraints`：最低现金、期限、折现口径和决策目标。缺阈值可报告结果范围，不擅自认定可承受。

缺少非关键资料时，先给明确假设下的草案或局部结果；资料补齐后只重验受影响部分。授权已覆盖的可逆工作继续，不重复确认。

## 执行

1. 统一现金口径、币种和时间粒度，区分实付与预计。
2. 按日期排列收付，计算滚动余额及首次低于约束的时点。
3. 建立基准和下行情景，将每个变化映射回原始驱动。
4. 单独运行敏感性，按明确现金流时点重算NPV或简单跑道。
5. 提出延后支出、分阶段投入等可审查选项，显示各自影响和依赖。

按需要读 [专业方法](references/professional-method.md) 和 [完整案例](references/delivery-template.md)。

## 交付

- `scenarioInputs`：情景输入。
- `cashTimeline`：日期现金轨迹。
- `sensitivity`：敏感性计算。
- `options`：行动选项。

## 检查结果

- 基准、下行与变化来源清楚，币种期间单位一致。
- 按真实收付先后定位最低余额和首次缺口。
- 一次改一个变量做敏感性，情景联动另外说明；NPV时点明确。
- 给影响具体缺口的可逆选项和复核点。

检查方法和证据要求在 [method.json](method.json)；参考 [作者正反例](evals/professional-cases.json) 识别实际错误。

## 需要额外处理的动作

实际融资、资金调拨和个性化投资选择按责任权限处理；模型和情景计算可直接继续。
