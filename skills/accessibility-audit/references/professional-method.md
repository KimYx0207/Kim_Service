# 可访问性检查与修复工作方法

## 目标与执行

用真实任务检查键盘、阅读器、焦点、文字和错误恢复，并把问题落实到修复位置。

1. 选主任务及空/错/加载状态，记录适用标准和测试环境。
2. 先用键盘完成流程，检查可达顺序、可见焦点、弹窗进入退出和返回位置。
3. 检查阅读器名称/角色/状态、表单标签与错误关联，验证动态状态是否可感知。
4. 检查缩放、文本对比和长内容，自动工具辅助发现规则问题。
5. 按受影响用户任务排序修复，同一路径复测并注明未覆盖范围。

## 关键判断

- 当自动扫描通过：继续关键任务手动检查；避免宣称全面符合标准。
- 当弹窗关闭：返回触发入口或合理后继；避免把焦点丢到body。
- 当多个问题：先修阻断任务的问题；避免全部同级阻断。

## 领域细节

对比度检查基于实际前景与背景组合，错误不能只靠颜色。禁用控件、只读控件和不可见元素的可达性按用途判断。无障碍名称应与可见标签一致便于语音输入。严重度按用户任务受阻程度评定，技术规则编号帮助复核而不替代实际操作。

## 输入不全时

- `surface`：页面/组件、关键用户任务和运行入口。可先审查设计与代码，标出未操作项。
- `target`：适用WCAG版本级别、浏览器、辅助技术和语言。以任务约束选择范围并记录。
- `evidence`：源码、现有扫描、用户反馈及复现步骤。先从关键旅程手动检查。

缺少非关键资料时，先给明确假设下的草案或局部结果；资料补齐后只重验受影响部分。授权已覆盖的可逆工作继续，不重复确认。

## 参考方法的用途

- W3C WCAG 2.2 quick reference：按适用成功标准检查键盘、焦点、名称、对比度和错误恢复。
- Storybook accessibility testing：为组件各状态配套可检查故事和自动化可访问性检查。
- Playwright best practices：围绕用户行为、独立测试状态和可重试断言编写测试。
