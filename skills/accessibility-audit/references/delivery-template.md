# 可访问性检查与修复交付示例与工作单

## 已完成的教学示例

以下输入为合成案例，数字和状态用于演示复核方法。

```json
{
  "surface": "报名表错误提示与确认弹窗",
  "target": "WCAG2.2 AA，Chrome键盘",
  "evidence": "无标签输入框、弹窗关闭焦点丢失"
}
```

- **findings**：姓名框缺可访问名称；关闭弹窗后Tab从页面顶部重新开始。
- **fixes**：关联label；错误用aria-describedby；关闭弹窗恢复触发按钮焦点。
- **coverage**：键盘路径复测完成；阅读器与其他浏览器另测，自动扫描结果单列。
- **priorities**：先修无法输入辨认与焦点恢复；色彩细节按任务影响排期。

## 为什么退回这一份

扫描替代任务：{"coverage": "axe零错误，所以所有残障用户都能完成所有任务。"}

错误原因：自动规则没有覆盖全部实际体验。

## 可以继续的局部结果

局部缺环境：{"coverage": "当前无阅读器，先完成键盘/语义检查并列阅读器路径待测；其他修复继续。"}

工具缺口不应阻断独立检查。

## 用于当前任务的工作单

| 交付项 | 本次应填内容 | 检查方法 |
| --- | --- | --- |
| findings | 每问题有位置、受影响用户、适用标准和复现步骤。 | behavior_probe |
| fixes | 语义、名称、焦点和错误提示与真实交互一致。 | behavior_probe |
| coverage | 区分自动、键盘、阅读器、缩放和各状态实际检查。 | artifact_inspection |
| priorities | 优先解决无法完成任务的阻断，给其余问题清晰排期。 | artifact_inspection |

用真实输入替换示例并保存产物位置。关键业务错误只阻断受影响的结论或操作；格式和解释完善不要求全任务停下。
