# 可访问性检查与修复

用真实任务检查键盘、阅读器、焦点、文字和错误恢复，并把问题落实到修复位置。

## 输入与开始方式

- `surface`：页面/组件、关键用户任务和运行入口。可先审查设计与代码，标出未操作项。
- `target`：适用WCAG版本级别、浏览器、辅助技术和语言。以任务约束选择范围并记录。
- `evidence`：源码、现有扫描、用户反馈及复现步骤。先从关键旅程手动检查。

缺少非关键资料时，先给明确假设下的草案或局部结果；资料补齐后只重验受影响部分。授权已覆盖的可逆工作继续，不重复确认。

## 执行

1. 选主任务及空/错/加载状态，记录适用标准和测试环境。
2. 先用键盘完成流程，检查可达顺序、可见焦点、弹窗进入退出和返回位置。
3. 检查阅读器名称/角色/状态、表单标签与错误关联，验证动态状态是否可感知。
4. 检查缩放、文本对比和长内容，自动工具辅助发现规则问题。
5. 按受影响用户任务排序修复，同一路径复测并注明未覆盖范围。

按需要读 [专业方法](references/professional-method.md) 和 [完整案例](references/delivery-template.md)。

## 交付

- `findings`：可复现问题。
- `fixes`：修复与回归。
- `coverage`：覆盖范围。
- `priorities`：修复顺序。

## 检查结果

- 每问题有位置、受影响用户、适用标准和复现步骤。
- 语义、名称、焦点和错误提示与真实交互一致。
- 区分自动、键盘、阅读器、缩放和各状态实际检查。
- 优先解决无法完成任务的阻断，给其余问题清晰排期。

检查方法和证据要求在 [method.json](method.json)；参考 [作者正反例](evals/professional-cases.json) 识别实际错误。

## 需要额外处理的动作

正式合规声明按实际覆盖与责任流程确认；页面检查、修复草案和已授权本地验证继续。
