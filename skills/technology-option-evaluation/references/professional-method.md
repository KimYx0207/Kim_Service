# 从项目问题到可推翻的技术选择

## 先定义选择的含义

把用户结果、受益者、付费方（如适用）、使用频率、可容忍等待、数据体量/语言/变更、权限粒度、部署位置、已有团队和预算放在同一项目上下文。`paid`、`internal`、`open-source` 可组合，阶段使用 `exploration`、`validation`、`delivery`、`scale`。内部项目可按节省时间、差错与采用率判断；开源项目可按复现、贡献与维护成本判断。商业试探也可以先验证需求，不要求探索阶段已证明规模化收入。

DAU、付费率、客单价、LTV 和交付负担分别影响约束，不能用“高 LTV”直接推导重架构。根据用户实际业务口径估算首次接入、每次操作、更新重建、存储、运行与人工维护成本；统一币种、期间和包含项目。未核实价格保留区间或待核，不用精确小数制造确定性。

## 研究的单位是决定

每个关键决定记录：当前假设、选项机制、支持证据、反证、适用条件、受影响需求、建议与翻转条件。检索围绕问题扩展：领域词/用户做法、替代机制、官方 API/版本、作者 GitHub 实现与测试、迁移/已知故障、运行维护与许可。关键词和仓库数量没有固定配额；每条新增材料应能改变一个判断或消除一个重要未知。

证据表保留 `id`、主张、URL/本地路径、作者或发布方、读取日期、文档/论文版本、仓库 tag/commit、适用环境、证据类型、限制、反证及消费它的决定 ID。把官方主张、当前代码观察、实际测量、人工观察、合成样本分别标记。一个官方文档证明接口承诺，不自动证明本项目性能。来源记录不能冒充本轮读取回执。

遇到术语混用先给可识别定义；例如 LLM Wiki、KV cache、RAG 不属于同一层。遇到冲突先核日期、版本、评测任务与实现，再决定采用范围。论文修订可能撤回旧结论，README 也可能落后于安装包；保留冲突，不把最新页面当所有旧版本行为。

停止条件：会影响选择的关键未知已有足够依据，或小实验的价值高于继续搜索；仍未知的项目明确其影响、负责人和重开条件。新需求、版本变化或关键实验失败只重查受影响决定，不把每次修改都变成全面调研。

## 形成比较并实际消费研究

列出可行机制，包含保留现有实现的基线；同一方案换名字不算另一条路线。每条写目标适配、数据生命周期、性能、成本、部署、维护、迁移和适用反例；任务不相关的维度写不适用及原因，不填虚构数字。

当前版本从锁文件、运行时输出、API 版本和安装组件取证。核模型 ID/修订、tokenizer、embedding 维度、索引格式、客户端/服务端接口、宿主扩展 API 中实际相关的一组。使用版本区间的包仍要记录本次实际锁定版本。升级不兼容时优先试可回退的小范围迁移，不能把 README 支持名称当组合兼容。

先满足不能交换的硬约束，再讨论偏好。若用评分，记录量纲、权重来源和敏感性；预算/权限失败不能靠速度高分抵消。结论必须说明哪条证据改变了哪个决定、为何拒绝另一条路线及什么结果会推翻推荐。只列来源或写“综合考虑”不算研究被消费。

## 小对照与专业评审

在看输出前固定数据快照、问题/场景、模型与工具版本、允许的变化、成本口径和失败判据。比较场景相同、资源口径可解释的候选；把调参题与留出题分开。对真实输出核质量、引用/事实、异常恢复、延迟分位数、单次与月度成本。记录样本数和不确定性；两个不同模型/预算/数据的结果不能直接归因于架构。

自动评分器先与独立人工样本校准。真实用户观察、独立 Agent 观察、作者构造输入和 helper 计算分开记录。测试时的澄清、方向提示、代执行、直接修复分别记录；不能把人工救援后的完成算完全自主成功。工具返回成功仅证明那次动作，专业效果依当前产物与独立评审。

## 交给本项目独立能力

在当前设计或任务交接中输出 `projectCapabilityRequirements`，每项包含：

- `projectId`、`baseComponentId`、`baseComponentVersion`：项目和全局专业基底。
- `role`、`responsibilities`、`boundaries`：本项目专业职责与相邻责任。
- `domainEvidenceRefs`、`projectDelta`：领域事实，以及较基底新增/收窄/替换的规则和理由。
- `requiredInputs`、`toolRequirements`：具体数据、版本、工具能力与缺失处理；发现、绑定和实际调用分别留证。
- `reuseConditions`、`targetPath`：跨次工作复用条件和项目内目标；已有项目包原地迭代，保留其定制。
- `acceptance`：能检出该专业失败的任务、反例与可观察结果。

这些是专业宿主创建独立包的设计输入，不是文件已存在的证据。全局库提供可维护基底；每个长期项目有自己的专业能力与规则。调用方管理创建产物、版本/digest、独立审核和权限。本包不另建 PRD、批准状态或调度器。
