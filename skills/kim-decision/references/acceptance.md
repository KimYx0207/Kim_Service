# 决策不是分数竞赛

## 判据的来源

先写“今天由谁在什么限制下选择什么”。硬约束（如本次现金上限、不得改变的用户范围）先筛选；偏好（速度、可维护性）才适合权衡。加权表必须说明尺度、权重是谁认可、区间和敏感性。把预算超标方案靠品牌高分拉回来，属于决策错误。

证据强弱按它支持的具体主张判断。一次真实访谈可证明这个受访者表达了某需求，不能证明整个市场愿付费；一个真实转化数据点若缺分母和窗口，不能评估效果。来源真实性、样本代表性和因果识别是不同问题。引用权威方法并不会自动让当前业务数据可信。

## 最小完整交付示例：买不买排班系统

这是合成场景，数字由案例给定，不能当市场统计。单人团队每周手工排班3小时、成本80元/小时，报价800元/月，现金上限600元/月，且不可降低排班准确性。

- 选择：本月买800元方案或继续人工。结论：不买；因为违反现金硬约束，收益再高也不能由分析者改写预算。
- 证据：报价与上限是用户提供事实；尚未实测节省比例和错误率。按4周演示，人工时间成本=3×80×4=960元/月，只是理论全部节省上界，不能声称实际净省160元。
- 备选：继续人工；询问不超过600元的版本。后一项未确认存在，不列为已获得方案。
- 下一步：如有预算内版本，取同一周历史班次离线排班，记录耗时、冲突数与人工修改量。人员权益、正式排班不随试用改变。
- 通过信号：费用不超过600元、无新增冲突；80元/小时×实测月节省小时大于实际月费。月化需要说明采用的周数和样本代表性；若节省仅1小时/周，4周仅320元，应拒绝600元方案。
- 决策边界：分析完成不代表采购已授权。用户若改变预算，应重算，不能复用旧结论当新批准。

## 拒收与恢复

“95分，建议立即买”不合格：没有证明满足硬预算。“14天必须上线”也不合格：任务是否需要两周取决于真实排班周期与资源。若缺少能改变选择的证据，交付 evidence-required、最小补证行动与停止条件；不要为了给答案而伪造确定性。

已有 models、master-lens、business、verification 用于选择合适思考工具；模型数量、引用人数、文字长度都不代表推理有效。可以只用一个适合的约束分析，也可能需要不同专业视角；每个视角必须改变一个具体判断。

## 加载与评估边界

执行本能力时按 SKILL.md 读取本文件及 method.json 中当前 capabilityId 的诊断、决策与 outputChecks。使用已有脚本和引用资料，不另造调度或运行状态。每条 blocking 规则缺证据或失败时保持未验收；其他高分不能抵消。作者自报 pass 最多是待独立复核的线索。

本仓库校验器验证合同、引用和示例格式；professionalEffect=not_evaluated。professional-cases.json 是作者合成的教学正反例，没有真实运行或人审发生性。当前 Meta 的 Skill 发现路径不会像 Agent 方法投影一样自动把 method.json 注入 worker；实际加载依赖入口的明确阅读规则和宿主支持，未观察则如实报告。原生宿主是否触发、业务效果是否改善，都必须另取当前版本的实际任务证据。
