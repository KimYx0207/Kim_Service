# 硬门

## 路径硬门

没有路径，不写完整方案。

必须有：

```text
主体
动机
理解
行动
阻力
信号
状态变化
延续动作
```

## 证据硬门

依赖下面内容时，必须查证或标未确认：

```text
时间
外部规则
外部系统
私有文件
高风险判断
当前市场状态
```

## 最小验证硬门

没有最小验证，不写大系统。

必须有：

```text
目标
输入
动作
输出
通过标准
失败信号
下一步
不做什么
```

## 无占位符硬门

不要留占位内容。

避免：

```text
待定
稍后
适当处理
视情况优化
提升体验
完善闭环
```

写清：

```text
执行者
输入
动作
输出
通过标准
```

## 根因硬门

重复失败时，先收集证据，再改方案。

必须有：

```text
现象
复现路径
最近变化
证据
假设
最小验证
```

## 完成硬门

说完成之前检查：

```text
验收标准
未确认事实
未处理风险
占位内容
可用结果
```

## 三次失败硬门

同一问题连续失败三次，停止继续改。

回到下面内容重新判断：

```text
意图
路径
根因
模型选择
缺失输入
范围
替代路径
```

## 研究硬门

当关键决策依赖 C 或 D 级证据时，必须先尝试验证。

步骤：

1. 找出哪些 C/D 证据如果升级会改变决策
2. 用可用工具搜索：联网搜索、文件读取、API查询、文档查找
3. 找到 → 升级等级（C→B 或 D→C），标注来源
4. 找不到 → 标记"未验证"，写明"无法验证，需用户确认"

规则：

- 关键决策不能只靠 D 级证据
- 每条关键 C/D 证据至少尝试验证一次
- 没有搜索工具时，跳过搜索但明确标记缺口

## 价值与阶段门

加载：references/business.md

在已有项目上下文记录可组合的 `valueTypes` 和当前 `stage`，按本次决定核适用价值与证据。探索可以先做有界验证；交付要有验收方式与负责人；扩大要核重复性、容量和适用的经济或非收入价值。

收费交付或扩大承诺要核收入模式、付款人、为何现在付、成交金额、交付成本及适用复购。一次性项目说明原因并核一次性经济账。缺证据只限制相关收费承诺，内部与开源价值不要求外部付款人。

## MVP硬门

加载：references/business.md

必须有：

```text
V1范围（一句话）
明确不做什么
实际时间和资源上限
受益者和验证场景
适用价值信号（交易、耗时/差错改善、可复现采用）
失败标准
```

首个结果应清楚有界；排除项用于消除真实范围误解。

## 交付硬门

加载：references/business.md

必须有：

```text
输入
处理
输出
验收标准
验收负责人和实际评审状态
有价值的复用
```

验收路径不完整会限制交付就绪；计划中的评审和已发生评审分开记录。已有授权持续有效，普通可逆工作不重复求批准。
