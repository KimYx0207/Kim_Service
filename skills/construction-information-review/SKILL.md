# 建筑模型信息交付审查

把模型信息交付要求与适用对象、属性值和实际验证结果对应，明确机器可检查与专业设计审查的边界。

## 开始前

- `requirements`：交付用途、对象适用规则、所需属性/分类/单位及来源 缺失时：未明确适用范围前不计算合规率
- `models`：已授权IFC/模型文件、版本、对象标识和导出信息 缺失时：没实际读模型只做要求审查，不宣称数据通过
- `validationContext`：IDS/工具版本、执行记录、专业审查范围与责任 缺失时：缺执行回执保留未观察

## 执行

1. 阅读 [工作方法](references/professional-method.md)，先确定适用条件与证据范围。
2. 沿 [专业方法](method.json) 的 `steps` 执行具体操作，再用 [完整交付模板](references/delivery-template.md) 整理当前产物；诊断问题与空字段不能充当完成。
3. 按 [专业质量规则](method.json) 中的具体输出规则选择检查方法，保存本次输入/产物定位及未观察项。
4. 对照 [作者正反例](evals/professional-cases.json) 检查常见专业错误；作者预期不算本次评测结果。
5. 把规则结果、实际产物、未决问题交回调用方；缺口仅影响相关结论。

## 交付

- `scopeMap`：要求与对象适用范围。
- `informationFindings`：对象级缺失和错误定位。
- `validationEvidence`：执行与工具范围记录。
- `handover`：整改与专业接受交接。
- `facts`：当前输入、来源、期间单位及证据缺口。
- `limitations`：未执行、未观察、方法假设和外推边界。
- `handoff`：当前产物、规则结果、证据定位与待解决事项交调用方。

## 关键验收条件

- `scopeMap`：每条信息要求有来源、版本、适用对象规则、属性含义/单位和例外理由。 拒收：只按名称猜对象，或把不适用对象混入分母。
- `informationFindings`：逐对象报告ID、属性/集合、实际值、预期规则、原因和来源位置。 拒收：只报总体百分比而无法定位缺失，或有字段即算值正确。
- `validationEvidence`：分开IDS规范文件有效、IFC可解析、模型满足信息要求三层，并记录实际工具/版本/输出。 拒收：校验IDS文件成功就宣称模型满足，或模拟报告当实际执行。
- `handover`：问题分配责任、修订/复查范围与正式接受边界，说明不涵盖几何和设计安全。 拒收：以属性齐全宣布消防/结构合格或替专业人员签章。

全部检查方法、证据要求和阻断标记以 [method.json](method.json) 为准。规则未执行时记录未观察；教学案例不是已经完成的专业评测。

## 边界

信息完整不等于结构、消防、几何碰撞或施工安全合格；不提供持证设计签章。

法定合规、结构/消防等设计判断和正式工程交付由相应有资质责任人确认。

只读本次指定材料；实际联网、命令、发布、业务变更或外部消息依当前宿主授权。方法不接管跨组件调度、持久记忆或最终验收。合同和示例检查不证明真实宿主或行业效果；无执行证据保留 needs_probe / not_evaluated。
