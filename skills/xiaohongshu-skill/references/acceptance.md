# 小红书图文包的可观察质量

## 从承诺开始验收

给标题里的每个承诺找正文和页面位置。“4步命名法”需要四项实质步骤、适用范围和一个完整例子；“效率翻倍”则需要可核实的定义、样本、比较和时间。没有后者就删这个承诺，不靠画面或文案气势补。真实感生成图可以用于示意，不得写成用户真实亲历、购买记录或使用效果。

平台条款按内容类型、适用主体与检查日期记录；交易笔记、商业合作和普通知识分享不同。官方规则用于确定真实与发布边界，不能推出“这样必火”。质量目标是内容有用、画面可读、承诺兑现；传播结果需实际发布后数据，创作者不能保证。

## 最小完整包示例：文件命名

合成题目是帮助同事在一个项目试用命名约定，无客户材料、无成效数据。完整生产需已有整套授权；否则只交可见封面MVP及待确认状态。

首选标题：“文件总找不到？先把这4件事写进名字”。备选8个见professional-cases.json，分别用具体困扰、反例、接收者检查等切口，不能用“100%提升效率”凑吸引力。封面候选文字：“文件名，先说清4件事”“别再猜哪份是最新版”“一个项目先试这套命名”，选择需绑定实际画面版本。

正文示范：文件名叫“最终版2”，发送时很确定，过几天又不确定了。可以先在一个项目里约定项目、内容、日期、版本。例如“春季活动_报名页_2026-11-10_v02”。项目说明归属，内容说明是什么，日期约定这一版的时间，版本区分修改。已有文档版本系统或客户模板时优先沿用现有规则。先拿一个最近项目试一周，请接收者找到指定文件；没改善就调整，不一次重命名全部历史。图中是示意文件，不是真实客户资料。标签：#项目协作 #文件整理 #工作方法 #资料管理。

页面完整安排：封面一张展示对比文件名并标示意；内页1给“最终版/最终版2”具体混乱；内页2解释项目；内页3解释内容；内页4解释日期含义，避免多人各自理解；内页5解释版本并说明已有版本系统例外；内页6给查找任务和试用检查单。各页必须有真实生成文件、准确文字和实际手机缩略图回看；本段导演表本身不是图片交付。

真正complete的报告含封面与6张内页的当前文件/预览、逐页文字检查、标题与正文、承接边界和素材缺口。归档保留当前工具证据及批准版本。没有真实素材就写“生成示意”；没有发布许可就写“发布草稿，未发布”。案例中的文案和页面安排是完整内容范例，图片仍需真实生产，不能把范例当已完成包。

## 反例与修复

- 四步标题只有三步：补有价值的第四步或改承诺；不能留空页凑数。
- 文字正确但缩略图上看不清：回到排版/路线规则，修后再看；机器字段校验不足。
- 旧同题图片替代本轮生成：先核用户是否明确授权复用；否则重做当前图片或报告具体阻塞。
- 单张封面认可扩为批量或发布：纠正许可记录；其他独立文案/来源整理继续。
- 已获完整生产许可仍只给脚本：缺用户最终产物，不能以“方法完整”交差。

沿用现有skill-contract的决策状态、图片路线和15段归档合同。本补充不建立新审批器、调度器或硬编码热点库。

## 加载与评估边界

执行本能力时按 SKILL.md 读取本文件及 method.json 中当前 capabilityId 的诊断、决策与 outputChecks。使用已有脚本和引用资料，不另造调度或运行状态。每条 blocking 规则缺证据或失败时保持未验收；其他高分不能抵消。作者自报 pass 最多是待独立复核的线索。

本仓库校验器验证合同、引用和示例格式；professionalEffect=not_evaluated。professional-cases.json 是作者合成的教学正反例，没有真实运行或人审发生性。当前 Meta 的 Skill 发现路径不会像 Agent 方法投影一样自动把 method.json 注入 worker；实际加载依赖入口的明确阅读规则和宿主支持，未观察则如实报告。原生宿主是否触发、业务效果是否改善，都必须另取当前版本的实际任务证据。
