# 业务指标口径契约

将业务问题转换成单一可追溯的指标定义，防止不同页面、SQL和报告使用同名不同义的数据。

## 开始前

- `question`：业务决定、目标人群和拟衡量行为 缺失时：先形成定义草案，不只命名指标
- `dataMap`：事件、实体、字段、关联、时间与数据源 缺失时：缺血缘或粒度时禁止给唯一确定值
- `policies`：纳排、去重、时间窗、退款/迟到、版本和负责人 缺失时：关键规则待业务确认，不能静默默认

## 执行

1. 阅读 [工作方法](references/professional-method.md)，先确定适用条件与证据范围。
2. 沿 [专业方法](method.json) 的 `steps` 执行具体操作，再用 [完整交付模板](references/delivery-template.md) 整理当前产物；诊断问题与空字段不能充当完成。
3. 按 [专业质量规则](method.json) 中的具体输出规则选择检查方法，保存本次输入/产物定位及未观察项。
4. 对照 [作者正反例](evals/professional-cases.json) 检查常见专业错误；作者预期不算本次评测结果。
5. 把规则结果、实际产物、未决问题交回调用方；缺口仅影响相关结论。

## 交付

- `definitions`：指标定义和适用解释。
- `lineage`：数据血缘与实现约束。
- `reconciliation`：可复算对账与差异。
- `changePolicy`：指标版本和变更影响。
- `facts`：当前输入、来源、期间单位及证据缺口。
- `limitations`：未执行、未观察、方法假设和外推边界。
- `handoff`：当前产物、规则结果、证据定位与待解决事项交调用方。

## 关键验收条件

- `definitions`：每指标写业务问题、分子/分母、粒度、窗口/时区、纳排和单位。 拒收：同名不同分母，订单数冒充买家数或人数与次数混算。
- `lineage`：每输入能定位到实体/事件/字段/过滤与连接，说明基数和迟到处理。 拒收：只给表名，或一对多连接放大度量而无控制。
- `reconciliation`：用相同边界按计数/金额/日期核对，差异追到规则和记录。 拒收：总额相同就宣布一致，或把未对上差值塞其他。
- `changePolicy`：语义改变有版本、生效日期、受影响消费者与历史可比性说明。 拒收：改分母但沿用旧名称和历史趋势，或多处独立修改失去单源。

全部检查方法、证据要求和阻断标记以 [method.json](method.json) 为准。规则未执行时记录未观察；教学案例不是已经完成的专业评测。

## 边界

不把指标命名当真实数据正确，也不替代数据所有者批准生产口径或财务披露。

经营结算、对外财务披露、考核奖惩或影响个人权益的指标由相应业务与数据责任人确认。

只读本次指定材料；实际联网、命令、发布、业务变更或外部消息依当前宿主授权。方法不接管跨组件调度、持久记忆或最终验收。合同和示例检查不证明真实宿主或行业效果；无执行证据保留 needs_probe / not_evaluated。
